## Terms

- **version-1 sidecar**: review staging stats sidecar classified `current-v1`; enforced by `validate_version1_payload` (`scripts/validate_review_staging.py`, def ~826). Versionless (`current`) sidecars keep legacy treatment.
- **F8 scalar gates**: the type-gate loop `for field_name in ("review_type", "artifact_slug", "date")` at ~870: required scalars skip `None` (the r5 F1 null gate stays the single reporter); a present non-string fails with `{field!r} must be a string`.
- **r5 F1 null gate**: rejects explicit JSON null for version-1 required fields, EXCEPT `selection_reason` and `escalation_reason` (the two documented null-when-not-applicable enum fields; carve-out at ~843).
- **findings loop**: the per-row loop in `validate_current_payload` at ~1224; `id_ok` predicate at ~1229; `valid_rows` at ~1223 (sort-safe rows) consumed by `validate_finding_order(valid_rows, result)` at ~1318.
- **RED/GREEN**: failing selftest fixtures land before the production gate; the gate flips them green. Selftest command in Validation Commands.
- **gate-unique phrase**: an error substring only the new gate emits, so a pre-existing error cannot satisfy the fixture (user-level lessons #235).
- **selftest families**: `_selftest_versioned_schema_and_patterns` (~3717) and `_selftest_current_contract` (~2221, with the `_run_id_fixture` runner at ~2364).

- assume the `round` gate skips None (the r5 F1 gate already reports required-null `round`) and accepts exactly a string or an int-that-is-not-bool; basis: contract table `agents/skills/review-staging/SKILL.md` line 338 plus the F5 bool precedent (bool is an int subclass in Python).
- assume `selection_reason`/`escalation_reason` null stays legal (existing F1 carve-out); basis: validator ~843-844 and SKILL.md lines 340-343.
- assume findings-loop fixtures extend the `_run_id_fixture` runner; basis: backlog item names it and the runner already covers the id-gate family.

- assume `source_kind` stays out of the gate set entirely: hashable mistyped values already fail its membership gate (~1138), unhashable values crash it (pre-existing, backlogged by Task 5), and a new type gate would double-report hashable mistypes; basis: r1 review F2 verification (plan review 2026-08-30).

## Gist & Examples

Verified silent-validation gaps in the review-gating validator: mistyped values pass hard validation and reach downstream summarizer cohort logic, and malformed findings rows validate clean or get misleading messages.

1. **`round` type gate.** Today `{"round": true}` and `{"round": 3.5}` pass `validate_staging_file(hard=True)` clean; a mistyped round silently misbuckets the summarizer's round-keyed cohort logic. After: both fail with `version-1 sidecar field 'round' must be a string or integer`. The documented dual typing is preserved: `{"round": 3}` and `{"round": "r3"}` stay valid (existing dual-typing guard stays green). Bool needs an explicit exclusion because `True` is an `int` subclass.
2. **Enum-reason scalar type gates (`selection_reason`, `escalation_reason`).** Today `{"selection_reason": 5}` passes hard validation (no type gate; the focused-panel truthiness gate is satisfied by any truthy value), same for `escalation_reason`. After: each fails with `{field!r} must be a string`. `source_kind` is deliberately excluded: hashable mistyped values already fail its membership gate (~1138, `source_kind must be one of ...`), and an unhashable value (a list) crashes that gate with a TypeError instead of a targeted error; that pre-existing crash vector is captured as a new backlog item in Task 5, and re-gating `source_kind` here would double-report hashable mistypes. Null handling is unchanged: `selection_reason`/`escalation_reason` null stays legal (F1 carve-out, full-panel payload).
3. **Duplicate finding-id gate.** Today two findings rows sharing `id: 1` validate clean; conservation reconciles both rows against their Markdown blocks and triage references like `F1` become ambiguous. After: hard validation fails with a `duplicate id` error naming the row.
4. **Missing-severity message.** Today a row with no `severity` key is reported as `has invalid severity (expected one of ...)`, so an author cannot distinguish an omitted key from a typo'd value. After: the row gets a dedicated `missing severity` error; present-but-invalid severity keeps the existing message.

Edge cases that shaped the design: the duplicate gate is error-only because equal ids at one severity are sort-safe (no TypeError), so `valid_rows` membership is unchanged; the missing-severity branch must not change `valid_rows` membership either (the severity-is-str append condition already excludes such rows); None-skips keep the r5 F1 gate the single reporter for required-field nulls (r4 F5 pin).

## Evaluation Criteria

- correctness: every mistyped shape listed in Gist fails `--hard` with its gate-unique phrase; every legal shape (`round` 3 / `"r3"`, enum-reason `null` and valid strings, unique ids, present severity) still passes.

## Design Invariants (CR Guard)

- **Dual-typed `round` stays legal**: `3` and `"r3"` keep passing (the existing dual-typing guard at ~4121 must stay green); only bool, float, and other non-{str,int} forms are rejected. The prior plan's "no gate may narrow round" freeze was scoped to that plan; this plan is its sanctioned follow-up but preserves both legal forms.
- **Null legality unchanged**: `selection_reason`/`escalation_reason` null stays legal (r5 F1 carve-out at ~843). The new type gates skip None so the null gate stays the single reporter (r4 F5 pin pattern).
- **No double reporting**: fields already owned by an existing gate are not re-gated; `source_kind` mistypes stay owned by its membership gate (~1138), so this plan adds no `source_kind` gate and no `source_kind` fixture.
- **Focused-panel truthiness gates unchanged**: missing/non-null-empty `selection_reason` reporting stays owned by the existing truthiness gates; this plan adds type checking only.
- **Findings-loop safety preserved**: both new gates are additive error reporters; `valid_rows` membership, the display-label attribution rules (r2 F2/F3, r3 F4), and the r3 F1 unhashable-severity protection are untouched. `validate_finding_order` stays frozen; no exception barriers are added.
- **Fence-scanner stack frozen**: the 2026-08-28-fence-scanner-consolidation contract (two-parameter `classify_fence_lines`, length-only close, event vocabulary) is out of bounds for this plan.
