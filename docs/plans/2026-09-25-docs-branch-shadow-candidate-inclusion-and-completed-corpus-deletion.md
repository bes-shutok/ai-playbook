## Terms

- **Shadow candidate**: an entry of `SHADOW_CANDIDATES` (the standard docs-tree entries, the facts `reviews_dir`/`tmp_dir` values, and the `extra_shadow_dirs` union parsed from live and docs-branch facts).
- **Bare-path probe**: `git check-ignore -q "<clean>"` on the slash-stripped candidate path. Verified git semantics (2.54/2.55, probed 2026-09-25 by two independent panels, index interaction triple-reproduced): for an untracked candidate a plain directory-only rule (`docs/history/reviews/`) already matches the bare candidate path, so it does NOT need the fallback; the descendant-only rule shapes (`docs/reviews/*`, `docs/history/reviews/**`) match children but not the candidate path itself and are the only shapes under which the bare probe fails while real ignored content lives inside. A candidate with ANY tracked file under it fails the bare probe even under a matching directory-only rule (check-ignore consults the index), so tracked candidates' inclusion comes from the mirror arm alone, before and after this plan. The high origin's plain-dir-rule witness premise is corrected here (its reviews dir is an untracked scratch root); every fixture in this plan uses a descendant-only shape so it discriminates.
- **Coverage-scoped descendant-ignored fallback**: the fallback probe applies ONLY to candidates with no tracked content under them (`git ls-files --error-unmatch -- "<clean>"` fails, recursive over the pathspec). A candidate with any tracked file under it (a wholesale root such as a live-tracked `docs/` tree) keeps today's inclusion paths unchanged: the bare gate decides untracked rule-matched candidates, the mirror arm decides branch-tracked ones, and a tracked candidate absent from the branch stays excluded exactly as today, so the fallback can never newly stage tracked product content and never widens a wholesale candidate from partially-ignored to fully staged.
- **Descendant-ignored probe**: for a fallback-eligible candidate, `git ls-files --others --ignored --exclude-standard --directory -- "<clean>/"` matched with the LITERAL containment needle `<clean>/` (fixed-string grep, no regex flavor). Verified output species under the pathspec: collapsed directory entries constrained to the candidate subtree (the candidate entry itself, emitted with trailing slash, and collapsed subdirectories at or below the deepest ignored entry) and individually ignored files. The pathspec excludes everything above the candidate (ancestors such as `docs/` never appear; they appear only in the pathspec-less variant) and everything beside it (siblings and prefix-siblings such as `reviews-old/`); non-ignored untracked intermediates are filtered by `--ignored` and never appear. The needle matches the collapsed candidate entry and every strict descendant; it is retained as DRIFT ARMOR for probe variants that drop the pathspec (the rejected classes), not because the pinned command emits them.
- **Mirror arm**: Step 2's `elif git ls-tree -r --name-only "refs/heads/${DOCS_BRANCH}" -- "<clean>"` continuity arm that re-includes a candidate already tracked on the docs branch and then wholesale-copies the live tree. Precedence pinned: a candidate ignored at bare level (or descendant level while fallback-eligible) takes the include arm and never reaches the mirror arm.
- **Loud skip**: the Step 1 warning arm for a candidate that exists with zero ignore coverage at any level, no tracked content, and no docs-branch presence (genuinely unsynced disk-only content); the warning stays a single line and its remediation enumeration names all sanctioned recoveries.
- **Ignore-else-track**: the standing design rule that tracked content is product content, not shadow content; unchanged for tracked candidates. A fallback-included scratch root stages its untracked-unignored remainder deliberately (a preservation root preserves what ignore rules missed; that remainder is untracked scratch, never product content, because the tracked-content gate already excluded tracked roots).
- **Partially-tracked candidate**: exists, fails the shared helper (the tracked-content gate refuses the fallback whatever the candidate's rule state), `git ls-files --error-unmatch` succeeds (at least one tracked file inside), untracked files live inside too, and the docs branch does not already track the candidate (a branch-tracked candidate is wholesale-synced by the mirror arm, so warning it would be false).
- **Close-in-place routing**: the corpus disposition convention for this plan: add or set the origin's `Status: closed` header (within the first 15 lines; two of the five origins carry no `Status:` line at authoring time, the checker accepts an added header, and both the bare and dash-prefixed bullet forms resolve) and add the `Disposition:` line AT THE LIVE PATH; no file moves and no additions to `docs/history/backlog/completed/`, whose README requires the inbox to stay empty of dated item files on both main and the docs branch. `scripts/check_plan_origins_closed.py` resolves a closed-in-place origin via the status header (its "closed in place (status closed/done)" branch). The fold-then-delete convention (per-item file deleted, disposition in the covering plan) is the recorded direction of travel once `2026-09-25-teach-origins-checker-fold-then-delete.md` lands; this plan does not assume it.

## Gist & Examples

Example of the discriminating fixture (the predecessor's vacuous-fixture defect made concrete): a scratch repo with `.gitignore` rule `docs/history/reviews/**`, an untracked candidate directory, and a live ignored file `docs/history/reviews/r1.md` fails the bare probe (`check-ignore -q docs/history/reviews` exits 1), passes the tracked-content gate (no tracked files under the candidate), and the fallback output (the collapsed `docs/history/reviews/` entry and the ignored file, exactly the two species the pinned pathspec emits) contains the literal needle `docs/history/reviews/`, so the helper includes the root; the same repo with plain rule `docs/history/reviews/` passes the bare probe directly and must include the root BEFORE and AFTER the fix, which is exactly the shape that made the predecessor's first fixture vacuous.

Example of the two scope guards working together: candidate `docs` in a repo where `docs/` is live-tracked with one ignored scratch file under `docs/other/**`: the tracked-content gate refuses the fallback (a tracked wholesale root never widens), the helper returns 1, and inclusion stays exactly today's behavior: the mirror arm includes the candidate when the branch tracks `docs/`, and a tracked wholesale root absent from the branch stays silent or receives the Task 4 warning (untracked content inside), never the disk-only loud skip, which requires a candidate with no tracked content. Ancestors and siblings never appear in the pinned probe's output (the pathspec constrains it to the candidate subtree); the literal needle is drift armor for probe variants that drop the pathspec, and its trailing slash still rejects a prefix-sibling (`reviews-old/` does not contain `reviews/`).
