# Certification seal landing diagnostic receipts

Append-only primary receipt ledger for the warning-only post-squash certification diagnostic in the plans skill's Plan Lifecycle landing-closeout bullet. One diagnostic run appends exactly one serialized receipt; receipts are never rewritten, reordered, or deleted.

Append contract: each receipt is written as one append-mode (`O_APPEND`) write, the complete receipt bytes are verified after the write, and a partial or mismatched write is an append failure routed per the receipt escalation chain (home: `docs/history/certification-seal-landing-diagnostic-write-failures.md`). Append order is receipt creation order; no lock is taken, and a storage failure never blocks plan closeout or promotes the diagnostic.

Receipt content contract: every receipt carries the repo-relative plan path and the highest ready review-record path, all landing-context proof command strings and results, both prescribed validator command strings, each validator command's result or `not run` state and reason (a command that did not run is never represented as executed), the matrix's warning value, and before/after landed OID, source-worktree HEAD, plan-byte, and seal-byte identities for each validator call and the full diagnostic. Every embedded path, command string, and captured output in a receipt uses the procedure's placeholder tokens (for example `<primary-checkout>` and `<source-worktree>`) or a repo-relative path, never a resolved filesystem root; a receipt that cannot be so expressed is a malformed receipt: express it in placeholder or repo-relative form before appending, and never accept a resolved-root append.

Outcome matrix: the single receipt outcome matrix (every result row, its receipt destination, and the fallback and transcript-recovery arms) lives in the plans skill's Plan Lifecycle post-squash diagnostic outcome matrix (`agents/skills/plans/SKILL.md`) and is the only source for receipt branch behavior; a run-identity mismatch routes directly to the fallback ledger as a mismatch record, distinct from a primary append failure, which routes per the matrix through the receipt escalation chain (home: the fallback ledger); the certifying plan's archived Task 2 matrix is a historical snapshot, not a second operative source.
