# Certification seal landing diagnostic receipts

Append-only primary receipt ledger for the warning-only post-squash certification diagnostic in the plans skill's Plan Lifecycle landing-closeout bullet. One diagnostic run appends exactly one serialized receipt; receipts are never rewritten, reordered, or deleted.

Append contract: each receipt is written as one append-mode (`O_APPEND`) write, the complete receipt bytes are verified after the write, and a partial or mismatched write is an append failure routed by the outcome matrix. Append order is receipt creation order; no lock is taken, and a storage failure never blocks plan closeout or promotes the diagnostic.

Receipt content contract: every receipt carries the repo-relative plan path and the highest ready review-record path, all landing-context proof command strings and results, both prescribed validator command strings, each validator command's result or `not run` state and reason (a command that did not run is never represented as executed), the matrix's warning value (`present` or `absent` read from the staging validator's observed stderr, or `not_observed` matrix-assigned when the staging validator did not run), and before/after landed OID, source-worktree HEAD, plan-byte, and seal-byte identities for each validator call and the full diagnostic.

Outcome matrix: the single receipt outcome matrix (every result row, its receipt destination, and the fallback and transcript-recovery arms) lives in Task 2 of the certifying plan `docs/history/plans/2026-10-20-certification-seal-landing-survival.md` (after archive, `docs/history/plans/completed/` under the same basename) and is the only source for receipt branch behavior. When an append into this file fails, the same receipt is appended once, with the primary-write error recorded, to `docs/history/certification-seal-landing-diagnostic-write-failures.md`; when both tracked appends fail, the receipt goes to the running maintenance session transcript, and the next maintenance sunset review owns recovery from that transcript into the fallback ledger before deciding whether no catch occurred.
