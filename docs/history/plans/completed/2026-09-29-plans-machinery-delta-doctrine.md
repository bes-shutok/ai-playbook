## Outcome

- Origins filed after landing carry one `Class:` line, fix-class or fence-class, whose default shape and driving force steer plan arms before any hardening is designed.

- A plan adding any runtime counted-class machinery without a paying sibling arm, a cited completed-integrity-failure witness, or (for a fix-class origin's refusal-path addition) an origin-cited no-exit justification addressing the class-default alternatives takes the existing machinery-without-witness review finding escalated to blocking, in place, with no second finding class.

## Terms

- **fix-class:** an incident where the system behaved correctly (failed closed, refused, stalled) but lacked a sanctioned exit, over-refused on a false positive, or forced a manual workaround. Default shape: add the sanctioned exit, remove the false positive, or simplify the flow. Driving force: simplicity or efficiency (at the backlog surface, the tag maps through the Backlog taxonomy's mapping rule). Acceptance names the block that disappears.
- **fence-class:** an incident where integrity actually failed: a wrong result, corrupted state, or lost evidence that a refusal would have prevented. Default shape: a new refusal, gate, or fence. Driving force: reliability in the Backlog taxonomy, or maintainability when the driving force is the plans code-quality tag (the plans closed set has no reliability, so a fence-class plan declares code-quality). The origin must cite the completed failure, never a saved manual step or a stoppable block.
- **counted classes:** the five machinery classes the Gate delta line counts: refusal classes, hard gates, fences, protocol layers, and schema state fields; the set adopts the symmetry origin's list as the scope of record. A **fence** is a runtime-facing refusal path that persists beyond plan review: a driver refusal, a gate check, a validation fence. The reviewer classifies each declared delta member, each payment target, and each counted-class addition the plan makes whether declared or not, by its runtime function and never by the plan's label: protection classes (hard gates, fences) prevent a completed integrity failure; ceremony classes (refusal classes, protocol layers, schema state fields) re-verify or record already-established state. Automation lanes stay outside the set (governed by the active-elimination rule and the machinery registry). A review-layer duty whose violation blocks is a **review-layer counted addition**: the Gate delta line declares it separately from the five, and its own text records its explicit-user-decision witness, which is a sufficient witness for review-layer counted additions (this plan's clause cites the 2026-09-28 adjudication together with the 2026-09-29 operator direction recorded in the symmetry origin's Source field; the surfaces are named by the origin's Location field and the rolling-log grouping entry). For the five runtime counted classes an explicit user decision alone does not witness an addition: only a paying sibling, a completed-integrity-failure witness, or the fix-class no-exit justification with its origin-cited bar does. A delta that grows an existing item's refusal surface or checked-condition set is an addition of the grown surface, not a keep or extend.
- **Gate delta line:** the required Outcome-region line declaring a plan's net machinery delta across the counted classes, additions priced and removals counted, plus any review-layer counted additions; the explicit none form when empty.
- **paying sibling arm:** a task in the same plan that deletes or simplifies a refusal class, protocol layer, or schema state field, paying for the plan's runtime counted-class additions in the same change set. Payment currency is ceremony machinery only: hard gates and fences never pay, because trading protection for new protection is not a net simplification. The payment target must itself be machinery present in the tree before this plan's change set (machinery the same plan adds never pays) and no old-form witness justifies it (the active-elimination bar), and "simplifies" names the concrete refusal, check, or field removed.
- **completed-integrity-failure witness:** the citation a runtime counted-class addition needs when it has no paying sibling: it must cite the specific recorded failure and where it is recorded (the origin body or an incident record) with enough specificity that the reviewer can re-derive it; recorded state left wrong or evidence lost; a saved manual step or a stoppable block is never a witness, and a conclusory citation that names no re-derivable record is not payment.
- **machinery inventory check:** `python3 scripts/machinery_inventory.py --check`, the standing registry check this plan must leave green and unchanged.
- **escalation clause:** the added sentence inside review-plan's existing machinery-without-witness finding that flips that same finding from ordinary to blocking when a runtime counted-class addition is unpaid.

## Gist & Examples

TLDR: incidents classify fix-class or fence-class when they file, plans declare their net gate delta, and unpaid fence additions take a blocking finding, because machinery growth was priced only at deletion time.

Today, every incident enters the pipeline with the same default shape, add a gate: a friction event files like an integrity failure, the plan declares code-quality, the review panel rewards thoroughness, and the fence lands. The witnessed conversion is on record: a consumer execute-plan scope-drift block, stoppable and recoverable by design, was filed with a reliability force and grew into a full hardening arm when the witnessed need was one sanctioned exit.

After this plan, the same incident files as fix-class, its plan removes the block or adds the sanctioned exit, and the acceptance criterion names the block that disappeared. A real integrity failure files as fence-class and must cite the completed failure it would have prevented. Every plan's Outcome carries the Gate delta line over the five runtime counted classes; an unpaid runtime counted-class addition, lacking any of a paying sibling arm, a cited completed-integrity-failure witness, or, for a fix-class origin's refusal-path addition, an origin-cited no-exit justification addressing the class-default alternatives, escalates the existing machinery-without-witness finding to blocking. Example Gate delta lines: a refactor deleting two ceremony gates writes `Gate delta: -2 protocol-layer checks (the x and y preflight re-checks), 0 added`; an adding plan writes the counted form shown in this plan's own Outcome; an empty one writes `Gate delta: none (no counted-class machinery added; none removed)`.
