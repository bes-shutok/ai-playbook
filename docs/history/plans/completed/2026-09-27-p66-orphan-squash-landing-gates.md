## Outcome

No plan-execution or authoring landing can move the default branch to a commit that severs its history without a loud, gated refusal.

- A landing parentage gate script refuses any landing whose new commit is parentless, has more than one parent, or whose parent is not the observed pre-landing default-branch tip; today every landing path trusts the machinery that produced the witnessed parentless squash commit 351f704f.
- A post-landing ancestry assertion refuses a landing after which the default branch no longer descends from the pre-landing tip or from origin/main, and distinguishes an origin-leg divergence that predates the landing from a landing-caused severance.
- The reverse-squash detector gains a commit-inspection shape that names the witnessed defect class: a parentless commit whose tree is a near-full-repo snapshot.
- A severed-ancestry landing rule pins diff-based landing as the only sanctioned path for branches with no merge base to the default branch, with the fork point recovered mechanically, forbidding merge, rebase, branch -f, and ref swaps onto the severed chain.
- The 2026-09-27 churn-prevention landing root cause is read from the surviving session record and its verdict recorded, and the executing session gates its own final landing with the same gate, closing the origin's open investigation duty without leaving the next landing ungated.

## Terms

- **Default branch / `<default>`**: the repository's primary branch (main in this repo); landing recipes pass it explicitly, never assume it.
- **Pre-landing tip (`PRE_TIP`)**: the default-branch ref value captured immediately before a landing commit or ref swap.
- **Orphan root / parentless commit**: a commit object with zero parents. The witnessed defect: squash commit 351f704f carried the full repository tree but no parent, severing 391 commits from main.
- **Near-full-repo snapshot**: a commit whose own tree contains at least SNAPSHOT_RATIO (the module constant, 0.5) as many files as the repository's tracked set.
- **Landing parentage gate**: `scripts/landing_parentage_gate.py`, the mechanical refusal point for the shapes above, with the guard-family exit contract (0 pass, 1 refuse, 2 tool failure).
- **Diff-based landing**: landing a branch with no merge base to the default branch by applying the branch's cumulative diff against its fork-point commit onto the current default tip and committing there.
- **Fork-point commit**: the branch creation start point, recovered mechanically as the object value of the oldest `git reflog show <branch>` entry whose message starts with `branch: Created from` (the message may carry a name such as main or HEAD instead of a sha; the entry's object value is the fork point in every form), or from the run's worktree-creation record.

## Gist & Examples

TLDR: landing-time parentage and ancestry gates, a parentless-snapshot detector shape, and a severed-ancestry diff-based landing rule now hard-fail any landing that would sever the default branch's history, closing the witnessed orphan-squash defect at code-quality's bar of mechanical enforcement rather than prose caution.

On 2026-09-27 03:58 the churn-prevention execution landed by moving main to commit 351f704f, a root commit: the squash machinery rebuilt the landing commit with an empty parent and swapped main onto it. Content survived (the orphan root carried the full tree), but main and origin/main had no merge base; 155 pushed plus 236 unpushed commits became unreachable until the 07:05 rebuild re-parented the squash and cherry-picked the seven descendants. The reflog entry had an empty operation string, the signature of a plumbing write (commit-tree, update-ref, or branch -f) computing the new commit with a missing or empty parent variable, instead of a normal commit on top of main.

After this plan, the same shape cannot land silently. Example: a temp-worktree arm landing builds `<new-tip>` and is about to run `git update-ref refs/heads/<default> <new-tip> <old-tip>`; the prescribed pre-swap gate invocation `landing_parentage_gate.py pre-swap --pre-tip <old-tip> --new-commit <new-tip>` exits 1 when `<new-tip>` is parentless or its parent differs from `<old-tip>`, the update-ref is skipped, and the run takes the deferred-landing path keeping the branch and worktree. Example: a primary-arm landing commits onto main and the post-landing invocation exits 1 because the default branch no longer descends from the captured pre-landing tip; the refusal routing dispatches on the leg first (an origin-leg-only refusal reports pre-existing divergence and keeps the landing), and a peer landed inside the capture-to-commit window means the stale-index landing is not confirmed - it rolls back with the `reset --merge` sequence and the landing defers for a fresh squash against the moved main, while genuine defect shapes roll back the same way, preserving peer unstaged changes outside the landing diff. Example: an audit of an already-landed suspicious commit runs `reverse_squash_guard.py check-commit --rev <sha>` and gets a named refusal when the commit has no parents and its tree carries at least half the repository's tracked files. Example: an execution branch forked from an orphan chain (no merge base with main) is landed by applying its cumulative diff, taken against the fork-point commit recovered from the branch reflog, onto the current main tip, the only sanctioned path, with the parentage gate re-run after the commit.

### Task 1: Landing parentage gate script and selftest

Files:

CLI contract (exit 0 pass, 1 refuse, 2 tool failure, mirroring the guard family):

- `pre-swap --repo ROOT --pre-tip SHA --new-commit SHA`: resolves both arguments as commits (`git rev-parse --verify <value>^{commit}`; an unresolvable NEW commit is a refuse, an unresolvable PRE-TIP is a tool failure); reads the parent set via `git rev-list --parents -n 1 <new>`; passes only when exactly one parent exists and it equals PRE-TIP. Refuse lines: `refuse: landing commit is parentless`, `refuse: landing commit has N parents`, `refuse: landing commit parent <sha> does not equal pre-landing tip <sha>`. Pass line: `ok: landing commit parentage verified`.
- `post-landing --repo ROOT --pre-tip SHA --default-ref NAME [--origin-ref REF]`: asserts `git merge-base --is-ancestor <PRE-TIP> refs/heads/<NAME>`; an unresolvable PRE-TIP or default ref is a tool failure (exit 2), and a merge-base exit other than 0 or 1 is a tool failure (exit 2); when `--origin-ref` is given and resolves, also asserts the ref is an ancestor; a given ref that does not resolve prints `note: origin ref <REF> absent; ancestry leg skipped` and does not affect the exit; the pre-landing-tip leg is evaluated first and its refuse line prints first, the origin-leg refuse line prints whenever that leg also fails, so a both-legs failure prints both refuse lines and exits 1. Refuse lines name the failing leg: `refuse: default branch no longer descends from pre-landing tip`, `refuse: default branch no longer descends from <REF>`. Pass line: `ok: default branch ancestry verified`.
