# The landing failure path gets a gate: single-command squash landing with path-exclusive restore, swap-time containment, and a post-landing staging invariant

- **Filed:** 2026-10-03
- **Driving force:** consistency (the landing pipeline's success path carries four gates while its failure path carries none; the closed taxonomy has no tag for an ungated state transition, and the three witnessed failures in one day are all that transition)
- **Plan review record:** the staging series docs/reviews/2026-10-03-plan-review-squash-landing-failure-path-guard-r*.md (the highest rN is the authoritative record, including any deferred-residual list; staged, gitignored reviews home)

## Outcome

The landing pipeline's failure path becomes mechanically gated where its success path already carries four gates. A new born-conformant helper `scripts/land_squash.sh` becomes the only sanctioned way to run a squash landing into a primary checkout: it refuses to run outside the merge lock (verifying the lock record's token, not merely a directory's existence), verifies the primary checkout's HEAD is the base branch at the caller's expected tip, snapshots `git status --porcelain` before touching anything, refuses the start when staged state exists or when a locally-dirty tracked path intersects the branch's changed paths (the record-only-dirt protection), runs the squash, and on ANY failure restores the index and worktree PATH-EXCLUSIVELY, exiting per the declared outcome mapping (indeterminate for the merge-failure and rollback arms; the gate's or precheck's fail class propagated otherwise) and naming the failure and every restored path. Its success arm asserts tree equality with the branch tip, builds the landing commit with `git write-tree` + `git commit-tree -p <expected-tip>`, and moves the base branch by two-value compare-and-swap `git update-ref`, with the parentage gate's pre-swap invocation (now carrying the new containment and base-pin legs) immediately before the ref move and the post-landing invocation (carrying `--origin-ref refs/remotes/origin/<resolved-base-branch>`, skipped by the gate when the ref is absent) immediately after.

The parentage gate's `pre-swap` mode gains two optional legs: `--source-branch <branch>` proves swap-time containment (the branch tip contains the live pre-landing tip via `git merge-base --is-ancestor`; a refusal names the fork-point merge base and the fork-point delta paths, the paths main gained since the fork that the branch lacks) and `--expected-base <sha>` verifies the recorded base pin (requires `--source-branch`; a tool error when given without it; the computed merge base of the pre-landing tip and the source branch tip must equal the base the run recorded at worktree creation, a mismatch proving a silent rebase under a stale record and refused naming both values).

The done sweep gains a `post-landing-staging` gate: in every closeout's pre-commit phase, the primary checkout's index must match HEAD except for staged paths owned by the resolvable current-session manifest (named as owned, the foreign-staging pattern), unstaged tracked modifications are permitted only for the record-only allowlist, a merge lock observed held at refusal time reports indeterminate (a landing is in flight, not a violation), and any other residue fails the closeout naming the residue paths, the sanctioned cleanup recipe (the helper's probe-then-reland path), and the operator escape for dead residue.

The landing discipline text is re-pointed: a pre-flight `land_squash.sh probe` (containment plus a `git merge-tree --write-tree` conflict trial, run WITHOUT the lock) gates lock acquisition, and conflict composition happens in the execution worktree before the lock, so the witnessed post-failure rebase becomes a pre-lock step.

`Gate delta:` additions: one new decision script (the helper, priced on all three witnessed incidents), two optional pre-swap legs (priced on the stale-base clobber 84d775a8 and the silent-rebase record class), one new done-sweep gate (priced on the pins-suite partial staging over b851f914), one reconcile report field (priced on the same clobber's manual --stat detection), five pins (pins-ride-behind-armed-behavior: the helper land invocation, the composite containment needle on EACH of the blueprint's two pre-swap invocation literals, the `base:` claim-line literal, and the staging-gate id; the execute-plan worktree-complete tail's `check-landing --source-branch` containment literal is deliberately NOT re-pinned here - its enforcement stays with the sibling plan's landed landing-tail wiring and this plan's blueprint needles, a recorded scoping decision rather than an omission), one claim-record schema field (the execution claim's `base:` line, priced on the 84d775a8 clobber's detection gap - the stale-base origin's Expected-2 record duty that makes a stale-fork landing diagnosable in one step instead of a manual --stat review), and one fault-seam selector variable with three declared test-only values plus its test-only target-path variable (documented in the contract row). Removals: none (no gate or recipe is deleted; the hand-composed primary-checkout squash recipe is retired by re-pointing text, not by deleting a gate).

## Gist & Examples

TLDR: the landing failure path gets the same mechanical gating as the success path - a single-command, lock-bound squash-landing helper whose failure arm restores path-exclusively and exits indeterminate, swap-time containment and base-pin legs in the parentage gate, and a post-landing staging-invariant gate in the done sweep - because three landing failures in one day (hybrid amend 9f832285, swept WIP 716e6443, partial staging over b851f914) all exploited the same ungated transition, and the nearest wrong recovery (blanket `git checkout -- .`) destroys the record-only peer dirt that must never be committed or reverted. Driving force: consistency.

Walk of the witnessed incident under this plan: a lane holds the merge lock, re-checks the tip, and runs `git merge --squash` in the primary checkout; ort fails over a peer's same-file landing and leaves the index partially staged with no MERGE_HEAD and no abort path. Under this plan that lane never hand-runs the merge: `land_squash.sh land --branch <branch> --expected-tip <sha> --message "..."` verifies the lock record and the checked-out base, snapshots porcelain, pre-refuses if the index is staged or a dirty tracked path intersects the branch's diff, runs the squash, and on the ort failure restores exactly the paths the failed merge staged (from the failure-time staged path set, each clean at snapshot, so restore-to-HEAD is byte-safe) and prints `OUTCOME: indeterminate` naming the conflict and the restored paths. The record-only file, dirty at snapshot and outside the branch's diff, is never in the restore set; had it been inside the branch's diff, the helper would have refused before the merge and named the intersection.

## Evaluation Criteria

- Each witnessed failure shape trips exactly one named fence in a scratch repo: a hybrid-amend class tip move trips the tip verification; a swept-WIP class dirty intersection trips the pre-refusal; a partial-staging class merge failure trips the path-exclusive restore; a stale-base class branch trips the containment leg; a silently-rebased branch trips the base-pin leg; a surviving staged residue trips the staging gate.
- The restore never restores a path that was dirty at snapshot time, never skips a path silently (every skipped path is named), and a dirty record-only path inside a branch diff is refused before the merge rather than restored.
- Every additive gate leg leaves the pre-existing parentage-gate fixtures byte-green; the one intentionally updated fixture is the done-sweep registry-order fixture, carved out in Task 3.
- An invocation of `land` outside a live, token-matching merge lock is a tool error and performs zero git mutations.
- Every prescribed validation command exits green from a fresh checkout of the run branch.

## Terms

- **Primary-checkout landing**: a squash landing executed with the base branch checked out in the primary checkout (the witnessed incident class). The worktree-complete landing critical section (execute-plan "Land under the lock") remains the sanctioned shape for plan-execution landings; the helper owns the primary-checkout class (archive riders, ad-hoc maintenance landings, manual recoveries) where the failures were witnessed.
- **Snapshot**: the `git status --porcelain=v1` output captured by the helper immediately after the tip verification, before the first mutating step. It records per-path state (staged, dirty-tracked, untracked), not content.
- **Restore set**: derived at failure time, never by re-diffing porcelain alone: the union of (a) the failure-time staged path set (`git diff --cached --name-only HEAD`, which is exactly the failed merge's residue because the index is verified clean at snapshot) and (b) untracked paths absent from the snapshot (merge-created conflict materialization). Paths changed since the snapshot that are in neither (a) nor (b) are a concurrent non-locking writer's write: the restore skips exactly those paths, restores everything else in the set, and exits indeterminate naming the skipped writer paths. Paths dirty at snapshot time are never restored (concurrent-writer bytes: they block and are named). Byte-safety assumes no peer STAGES during the critical section (staging in the primary checkout during a landing is a landing-gate violation); a violating peer's staged bytes sit in set (a) and restore to HEAD like merge residue - the recorded residual. A blanket `git checkout -- .` / `git restore .` is forbidden everywhere in this plan's surfaces. The record-only path's protection is solely the dirty-intersection pre-refusal: a dirty record-only path inside the branch's diff refuses the landing before the merge; a clean one inside the diff is branch content and restores byte-safe like any tracked path.
- **Record-only allowlist**: the dirty-path class that must never be committed or reverted by any landing step: `projects/.ai-playbook/development_lessons.md` (the standing peer edit; the witnessed survivor of the selective 2026-10-03 recovery). Constant owned once, in the staging gate (Task 3), with a provenance comment; the helper carries no copy - its dirty-intersection pre-refusal is allowlist-agnostic and is the record-only protection.
- **Operator escape (dead residue)**: the staging gate's refusal names it: with `done-lock.sh merge-status` reporting free and a per-path check that the path is not peer-live dirt, restore each residue path individually (`git restore --staged --worktree -- <path>`); record-only allowlist paths are never escapable.
- **Containment proof**: `git merge-base --is-ancestor <pre-landing-tip> <source-branch-tip>` must hold at swap time; CAS protects ref movement, not tree containment (the stale-base row's root cause). The helper's probe runs the same one-line check inline (deliberate: the probe cannot carry a `--new-commit`, so it does not invoke the gate; two single-line `git merge-base --is-ancestor` calls, one in each mode, are priced below the machinery of a third gate mode).
- **Base pin**: the worktree's base commit recorded at creation (the run manifest's `run_base`; the execution claim gains a `base:` frontmatter line via the claim's refresh cadence once the worktree exists - the claim is written before the worktree, so the line is added at the first refresh after creation, not at first write). A SANCTIONED rebase (the probe-gated pre-lock rebase duty) ends by refreshing the recorded pin - the manifest's `run_base` and the claim's `base:` line - to the post-rebase merge base, before `land` runs; a pin mismatch therefore means the record was not refreshed across a rebase, which is the silent class the leg refuses. The helper's `land` mode takes an optional `--expected-base <sha>` (the caller's current recorded value) and forwards it to the gate's leg; an invocation without it skips the leg (the claimless ad-hoc class carries no pin).
- **Probe**: the helper's pre-lock mode: containment check plus a `git merge-tree --write-tree` conflict trial; gates lock acquisition, mutates nothing.
- **Fault seam**: `LAND_SQUASH_TEST_FAULT`, a test-only environment variable with three values, each honored at its single declared point: `backward-peer` fires immediately after the CAS succeeds and moves the base to `<expected-tip>~1` (a commit that does NOT descend from the pre-landing tip - moving to the pre-landing tip itself would keep the gate's ancestry leg true, since a commit is its own ancestor, and produce a vacuous pass), so the post-landing pre-tip leg refuses with main left at the fault commit; `diverge-origin` fires at the same point and redirects the post-landing invocation's `--origin-ref` to a forged throwaway ref under a test namespace (`refs/remotes/land-squash-fault/diverged`, created BY THE FIXTURE at a commit that is not an ancestor of the landing commit - an absent ref is a named gate skip, not a refusal) instead of rewriting the real remote-tracking ref; `dirty-writer` fires immediately after the snapshot and appends one line to the tracked path named by the test-only `LAND_SQUASH_TEST_FAULT_PATH` (a path outside the branch's diff, pre-created by the fixture), exercising the changed-since-snapshot writer block. All three are declared test-only in the helper's contract row; production never sets them.
- **Inverse CAS**: the rollback `git update-ref refs/heads/<base> <expected-tip> <landing-commit>`, whose old value is the landing commit captured at landing time and never re-read; because a landing commit always descends from the pre-landing tip, any state that trips the post-landing pre-tip leg also has main differing from the landing commit, so the reachable failure arm is the inverse-CAS REFUSAL (a peer tip move: keep the landing, restore, exit indeterminate citing the interleaved tip) - the clean rollback-landed arm is unreachable through the pre-tip leg and is not a fixture target.
- **Born-conformant**: the helper ships under the script outcome contract from its first commit: four exit codes (0 pass, 1 fail, 2 indeterminate, 3 tool error), a final `OUTCOME:` line on stdout for every non-metadata run, and a declared assumptions row in `scripts/OUTCOME_CONTRACT.md`.
