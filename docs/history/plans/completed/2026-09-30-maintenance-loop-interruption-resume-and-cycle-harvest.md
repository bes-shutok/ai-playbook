# Standing-directive loops must resume after interrupting tasks, classify their mandate once, and harvest findings every cycle

[github: https://github.com/admitriev/ai-playbook] Backlog origin: `docs/history/backlog/2026-09-30-maintenance-loop-interruption-resume-and-cycle-harvest.md`
Driving force: reliability

## Gist TLDR

TLDR: close the interruption-shaped hole in the maintenance skill's continuation machinery and finish the loop-state record, so a standing user directive survives ad-hoc user tasks, its lane mandate is classified once into durable state, and every completed cycle harvests findings through learn and investigate before the next selection.

The continuation machinery is landing-boundary-shaped: the interactive continuation bullet (the execution lane's one home) forbids the closing report-and-stop shape only at the post-landing boundary, the in-session authoring chaining bullet covers only the authoring-to-execution boundary, and the continue-loop condition covers only lane decisions. No rule covers returning to the loop after an ad-hoc user task that is itself neither an authoring nor an execution cycle, and the resumed-turn rule's conservative default (report readiness and stop) is the only interruption-adjacent text, biasing to stop at exactly the boundary where the directive should resume. Witnessed 2026-09-30: a session ran six interleave cycles, then two ad-hoc filing turns each ended the session until the user re-prompted. Three of the item's four arms partially exist already and only their missing halves are built here: the `loop_mode` field and its write class exist but no classification mapping from directive text to mode; `authoring_cycle_gate` and the resumed-turn rule exist but the state carries no cycle count and the readiness report names nothing; learn is wired nowhere in the maintenance loop and investigate only through the scheduler turn's rolling prompt log duties.

## Outcome + Gate delta

## Terms

- **Standing directive**: a live continuation directive per the interactive continuation bullet's liveness wording (live from its utterance until withdrawn, the queue empties, or the context genuinely runs low); where the session records `loop_mode`, the field's `directive` member carries the wording.
- **Ad-hoc interrupting task**: a real user message asking work that is neither the loop's authoring cycle nor its execution cycle (analysis, filing, bookkeeping, a question).
- **Cycle**: one completed authoring landing or execution landing under the standing directive.
- **Counted cycle**: a cycle closed by a session meeting the cycle-gate write class's writer condition (a standing directive whose text gates the next cycle on a user-side action); only such closeouts increment `cycles_completed`, and only the resumed-turn report reads it.
- **Loop mandate**: the `loop_mode` field's mode classification (`authoring-only`, `execution-only`, or `dual`).
- **Harvest**: the per-cycle duty of running learn over the cycle's outputs and one investigate pass over findings witnessed during the cycle.

## Assumptions

- Composition, not bypass: resuming the loop means re-entering the existing machinery (the continue-loop condition, the lane guards, the cycle gate, the quota leg, the locks). An armed `authoring_cycle_gate` still stops a resumed loop attempt with `cycle-gate-armed` and its sanctioned-exemption semantics; the interruption-resume rule changes where the session goes after an ad-hoc task, never which holds apply. Basis: the cycle gate's stated purpose (an unattended loop cannot silently defeat a user pacing gate).
- The resumed-turn rule's conservative default is unchanged; only the readiness report's content improves (it must name the live loop instead of generic queue readiness). Basis: the rule exists to stop a summary-resumed session from starting a cycle no user asked for.
- `cycles_completed` rides `loop_mode` as an additive optional integer key under schema 4 (no version bump), the same treatment the withdrawal `cleared_at` trace already received. The increment rides the existing cycle-gate write class and only fires under that class's own writer condition (a pacing-gated closeout), so loops without a pacing leg carry no count and no new writer class exists (the sanctioned-writer lead-in count sentence stays at eight; the class enumeration entry gains the increment leg beside the gate arm). The increment is a targeted member edit that preserves the field's `set_at` and is never a directive write for the Step 0 freshness test (no cannot-decide listing per closeout); a directive withdrawal drops the count, so a fresh directive starts from zero. Basis: the additive-key precedent and the writer condition in the same paragraph.
- The harvest invokes the learn and investigate skills and never restates their rules. The investigate leg defers wholly to investigate's own contract: one artifact, the single rolling prompt log entry; its input is the highest-priority ungrouped open item among the findings the cycle witnessed (the scheduler-turn form's selection rule); a witnessed finding with no matching open item is first filed through receiving-review's Backlog capture as ordinary loop work, outside the pass, and the pass then investigates it. Basis: the investigate skill's hard gates and its existing maintenance entry's selection rule.
- Scheduler-turn dedup: when a cycle's closeout is a scheduler turn whose rolling prompt log duties already ran their investigate leg, that leg satisfies the harvest's investigate leg for that cycle (both produce the log entry), so the duty never double-runs. Basis: the same turn would otherwise run two investigations of the same corpus.
- Ambiguous directive text classifies `dual` with the ambiguity recorded in the field's `note` member: `dual` and `null` are inert (today's behavior), so an ambiguous record cannot misroute a lane, and the note carries the resolution for the next classification. Basis: the field paragraph's own inertness clause.
- Companion pins register the new contract literals in `scripts/check_maintenance_pins.sh` so their later deletion fails a pin instead of passing silently; the suite runs as a validation command. Basis: the maintenance SKILL.md Revisions precedent (the 2026-09-26 P64 entry registered companion pins for the same class of change).
