## Outcome

Review certification at the plan-bytes and code-review boundaries distinguishes provably semantics-preserving deltas from decision-bearing ones, so only a real change forces a fresh review round, and an uncertain delta stops for the operator instead of guessing.

- A typography-only plan edit, a forward checkbox flip, or a comment-only code fix re-binds certification through a recorded, script-produced, validator-verified correction with zero rounds, uncapped (today each forces a full extra round; two witnessed em-dash recert rounds paid it on the plan side, and any accepted fix buys a fresh adversarial round on the code side).
- A delta the classifier cannot prove stops the run with the diff shown and waits: an unattended run takes the default re-review, and the operator may authorize a re-bind with a recorded ack whose witness and classifier-gap row the validator resolves out of band and binds to this delta's subject, so acked delta classes mechanize over time.
- Identity and integrity digests (CAS old-values, expected-tip pins, resolve-at-use re-derivation, tree-equality gates, the terminal gate's archive fencing, the authoring watcher's per-tick drift fence, the evidence_contract_digest mapping) stay strict; equality is the check there and nothing in this plan touches them.
- Nobody fixes typography by hand: the plan-edit path mechanically substitutes em dashes (comma, per agent_workflow_guidelines.md section 39.1) outside excluded regions before bytes land, and boundary scans auto-fix residue as recorded typography-class corrections.

## Terms

- **Excluded region**: a byte region the plan-bytes classifier never exempts: fenced code blocks (backtick and tilde forms, with their info strings), inline code spans, indented code blocks (four-space or tab after a blank line, including list nesting), setext underline lines, thematic breaks, table delimiter rows, and link destination spans (the `](...)` target and `<...>` autolinks; the origin row's "paths" member lands here); a fenced region left unclosed extends to end of file. Heredoc bodies in Bash are data, not comments, and are excluded the same way on the code side. This set is this plan's fail-closed superset of the origin row's "fenced regions"; the row's "paths" member is covered by the inline-code-span and prose rules rather than a separate class.
- **Exempt class**: a hunk classification the classifier can prove semantics-preserving, per surface. Plan bytes: `checkbox-flip` (only the forward `- [ ]` to `- [x]` flip on an otherwise byte-identical line; the reverse flip, `- [X]`, and any other same-line byte change are unclassified), `whitespace` (whitespace-run collapse, blank-line add or remove, constrained to structure-preserving shapes: the leading-indent quantity class of each affected line is unchanged across the collapse (the class is the leading whitespace normalized with a tab counted as four columns, bucketed as zero, one to three, or four or more), and a blank-line add or remove is not adjacent to a four-space-or-tab line whose block type would flip; a change to a line's trailing hard-break spacing, or one that flips a list between loose and tight form, is unclassified), `typography` (the punctuation-equivalence map: em dash to comma (the section 39.1 fence form, the only em-dash arm; legacy hyphen, colon, and semicolon shapes are unclassified and take the ack path); en dash to hyphen; each with single-space normalization and never adjacent to a digit on both sides, so numeric ranges are unclassified; a typography hit on a heading line is left for the operator ack path, never auto-exempt; curly quotes to straight; the ellipsis character to three periods; non-breaking space to space), each recognized only on lines outside excluded regions, and case is never normalized. Code: `comment-only` (per-language proof that every changed line's code content is byte-identical and only comment content differs, trailing comments included), excluding docstrings (runtime visible, doctests execute), the directive-comment family (`noqa`, `eslint-disable`, `type: ignore`, `shellcheck disable`, `fmt:`, `isort:`, and the file-level forms `ruff: noqa`, `pylint: disable`, `flake8: noqa`), PEP 263 encoding declarations on lines 1-2 in any spelling (runtime load-bearing and decode-bearing), heredoc bodies, and generated files.
- **Unclassified delta**: any hunk the classifier cannot prove exempt. It never re-binds by itself: the run stops, the diff is shown, the default is a fresh review, and only a recorded operator ack (below) can turn it into a re-bind; an out-of-process unclassified delta takes the same stop-and-adjudicate path, with reverting to the reviewed bytes as the disposition when the operator declines.
- **Certification correction**: one recorded re-bind hop, a row in the review sidecar's `extensions.corrections` array, produced by a classifier CLI (`--emit-row`), never hand-authored; kinds `script-verified` (every hunk carries an exempt class) and `operator-acked` (unclassified hunks covered by a complete operator ack receipt); fields `kind`, `before_digest`, `after_digest`, per-family evidence fields (`evidence_commit` for plan rows; `before_base`/`before_head`/`after_base`/`after_head` for code rows, the three-dot diff recipe's refs), `hunks`, `recorded_at`, `recorded_by`. Every hop is non-vacuous: `before_digest` differs from `after_digest`, `hunks` is non-empty, and the chain contains at least one hop.
- **Operator ack**: the operator-adjudicated re-bind receipt on an `operator-acked` row, bound to this delta's subject: the operator's directive text, an `authorization_witness` resolving to the scheduler state file's turn record (the one surface sessions do not author directly) whose bytes echo the subject (the certified artifact's path and the row's before and after digests), carry the operator direction as a named field, and name a turn-record writer different from the row's `recorded_by`; a commit-trailer-only witness is not a turn record and refuses, and a `classifier_gap_row` path under this repository's docs/history/backlog/ that must exist with proposal text quoting the refused hunk's digest.
- **Classifier-gap row**: the backlog row in this repository's docs/history/backlog/ that every operator ack files, proposing the mechanical bucket that would have covered that delta, so acked classes mechanize over time; rows file here, never in the consumer project's backlog.
- **Certification seal (both families)**: the committed record file `docs/history/review-certs/<artifact-slug>.md`, one entry per round, written and committed by the round-close step after the round's folds land (so no entry ever needs to name a commit that contains it). Each entry carries: round, the artifact path, the round-start commit (the artifact-path commit whose bytes the round reviewed), the round-start digest, the round-close commit, and for code rounds the certified range (`reviewed_base`, `reviewed_head`) with the regenerated diff digest. The seal is the single out-of-sidecar certification identity for both families and is read from git. - **Round-anchored reviewed digest**: the anchor of every corrections verification. The sidecar's declared `source_digest` must equal the round-start digest of the seal entry for the sidecar's round, the entry's round-start commit must be an ancestor of HEAD whose blob (plan family) or regenerated three-dot diff (code family) re-hashes to that digest, and a verifying record must chain from it; a declared digest matching neither the seal entry nor a verifying record refuses as an unwitnessed mutation. Every hop is digest-bound: each row's declared digests must equal the sha256 of the bytes re-derived from git at that hop's evidence, never merely chain among declared values. A bare `source_digest` rewrite, a moved or self-minted seal entry whose commit postdates its claimed round, an unbound declared digest, a vacuous hop, and a zero-hop chain all refuse. The classifier excludes the seal path from code diff classification, so a seal commit never fails an honest hop.
- **Seal integrity**: the seal entry for a round is written at that round's close; every hop commit of a corrections chain and the terminal state must postdate the seal entry's round-close commit, and an entry whose round-close commit is not an ancestor of HEAD, or a sidecar range differing from the seal's certified range, refuses naming the seal leg. The seal file is append-per-round; replacing or editing an existing entry is a visible git commit that the hop-commit dating detects.

## Gist & Examples

TLDR: Certification re-binds through script-verified corrections for provably non-semantic deltas in plan bytes and code diffs, stops for the operator on anything unprovable, and ends the full extra round that any byte change forces today.

The binding's own rule text concedes the plan-side defect: plans rule 2 says "A fold is a digest change, regardless of severity", rule 29 says "any post-certification byte change forces a fresh certification round, because the digest binding makes no distinction between a formatting fix and a semantic fold", and two em-dash recert rounds (2026-09-04 and 2026-09-05) each paid a full panel for typography. The code side pays the same tax: execute-plan Phase 3 says "Any accepted fix mutates the source and requires a fresh targeted review of the new digest", so a comment-only fix buys a fresh adversarial round. The execution lane's Step 0.5 already owns the vocabulary (a `plan_correction:` manifest line, a checkbox-flip resume exemption) but the gates grade nothing.

This plan grades both families with one doctrine and one shared record machinery. A classifier script (never agent judgment; the editing session records the script's output, it must not classify its own edit) diffs reviewed versus current bytes and buckets each hunk into the surface's exempt classes; hunks inside excluded regions and any code hunk that is not provably comment-only are unclassified. A fully exempt delta records one correction row (produced by the CLI's `--emit-row`) in the review sidecar's `extensions.corrections` array and continues with zero rounds; the validator re-derives every hop from git (plan blobs at the seal entry's round-start commit; both diff sides via `git diff <base>...<head>` from the certified range), binds every declared digest to those re-derived bytes, refuses vacuous hops and unsealed or postdated claims, and accepts or refuses with a distinct reason. An unclassified delta stops the run and shows the diff: unattended, the default re-review applies; the operator may ack the re-bind, whose receipt the validator resolves out of band and binds to the delta's subject, and the gap row proposes the missing mechanical bucket. Worked example: a clean round r5 certifies plan digest D1; an em-dash fix moves the bytes to D2; the classifier emits one `typography` row; plan_readiness re-derives D1 from the seal entry's round-start blob, verifies the non-vacuous hop, and passes with no r6. Code example: a review certifies the range (base, head) with digest X and records both refs; a follow-up committed fix changes two trailing comments; the row's before refs equal the certified range, the after side chains one commit forward, the verifier regenerates both diffs, the code classifier proves comment-only, and no fresh adversarial round runs; a docstring or encoding-cookie edit would be unclassified and stops. The em-dash fence closes the loop at the source: the plan-edit path substitutes before bytes land, and boundary scans auto-fix residue as recorded typography corrections.

## Evaluation Criteria

**Quality dimensions:**
- correctness: every exempt class is pinned test by test in both polarities with a near-miss fail witness per class; the validators re-derive every hop from git bytes and refuse any unproven delta with a distinct reason.
- security (fail-closed): the editing session cannot classify its own edit past the gate (rows are CLI-produced, validator-re-derived, digest-bound to re-derived bytes, and anchored at the committed seal entry's round-start commit); a moved anchor, an unbound declared digest, a vacuous hop, and a bare rewrite each refuse by name; an unattended run's control for an unclassified delta is the stop-and-adjudicate default, hardened by a subject-bound, writer-checked ack receipt.
- maintainability: one shared corrections-record module behind both families; one classifier implementation per family shared by every consumer; vocabulary and substitution-map literals are pinned so widening them is a visible reviewed change.
- simplicity: the fresh-adversarial doctrine is preserved by construction (only provable deltas skip rounds); identity digests untouched; no cap, no new human-mandatory step on the happy path.

**Done when:**
- a typography-only plan edit with a recorded script-verified correction passes the readiness gate; the same bytes without the record fail with today's stale reason; a bare `source_digest` rewrite, a seal entry moved after its round, and a vacuous hop each refuse as unwitnessed mutations; an Assumptions word change fails even when a row claims otherwise (fixture-proven in scripts/test_plan_readiness.py).
- a comment-only Python fix and a comment-only Bash fix (trailing comments included) re-bind a code review's digest with zero rounds via the certified range's refs; a docstring edit, an encoding-cookie edit, a directive-comment edit, and a heredoc-body edit refuse as unclassified (fixture-proven in the code classifier selftest and the staging selftest).
- an unclassified plan delta stops and accepts a complete ack receipt whose witness record exists, echoes the delta's subject, and whose gap row exists quoting the refused digest; an incomplete receipt, an unresolvable witness, a subject mismatch, or a dangling gap-row path refuses naming the missing piece.
