## Terms

- **Landing gate:** the owning closeout check that proves branch content reached the sanctioned destination.
- **Preservation archive:** a verified full-history copy retained before an explicitly directed local resource removal.
- **Exact-ref removal:** deleting a branch only when its current object id still matches the object id verified for removal.
- **Worktree inventory:** the tracked, untracked, and ignored files present in a linked worktree, each with a verified destination before its removal.
- **Quiesced owner:** the resource's owning run has reached its authorized closeout and every writer that could change the resource has stopped.

## Why

Self-heal currently preserves local workflow instructions as hard stops even when the user explicitly directs an in-scope recovery. Its cleanup outcomes also do not describe a user-directed removal when the landing gate correctly refuses and the resource can be safely preserved. The done closeout's branch-removal rule also needs a cross-reference to that separate outcome so the two skills do not conflict.

## Gist & Examples

TLDR: clarify user-direction precedence and separately report preserved cleanup across self-heal and done, improving code-quality while reducing avoidable recovery stops.

When the user explicitly authorizes removal of a named local branch after a landing gate refuses, self-heal can remove that exact ref only after the owning run is closed, every writer is quiesced, its full history is preserved, and no linked worktree remains. Removing a linked worktree also requires the user's direction to cover that worktree and a verified destination for each tracked, untracked, and ignored item. It reports each removal separately from the still-failed landing gate. If authority, ownership, preservation, worktree inventory, linked-worktree state, or ref identity is unclear, it retains the resource and names the missing decision or evidence.

## Outcome

Self-heal and done follow explicit user directions that are within the user's authority and report each cleanup result without changing the status of a refused gate.

- Recovery continues past conflicting lower-level local instructions when the user's current direction clearly covers the next action and no higher-priority constraint blocks it.
- A named branch can be removed after the owning run is closed, writers are quiesced, its complete history is preserved, no linked worktree remains, and its exact ref identity is verified; the failed landing gate is reported as failed.
- A worktree can be removed only when the user's direction covers it and every tracked, untracked, and ignored item has a verified destination; otherwise it stays in place.
- Unclear authority, an active owner or writer, incomplete preservation, a linked worktree, or ref drift results in retention and a specific evidence request.

Gate delta: no validators, gates, machinery, fields, or review-layer blocking duties are added or removed. The two incident-backed backlog origins document why a distinct non-landing cleanup disposition is needed; existing closeout ownership, writer-quiescence, preservation, and explicit-direction requirements bound it.
