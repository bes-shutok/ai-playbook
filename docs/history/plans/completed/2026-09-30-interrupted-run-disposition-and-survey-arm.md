# Interrupted done runs close once: a disposition record for unadoptable manifests, a survey classification arm, and same-turn capture commits

[github: https://github.com/admitriev/ai-playbook] Backlog origin: `docs/history/backlog/2026-09-29-interrupted-run-and-stranded-work-prevention-ideas.md`
Driving force: reliability

## Gist TLDR

TLDR: of the origin's six prevention ideas, this plan builds the three the origin itself ranks first and records where the other three live: a `disposition-manifest` operation and `dispositioned` record give an unadoptable interrupted done run (its recorded root digest names a checkout that no longer exists, so adopt and finalize refuse forever) a sanctioned one-time closure with a verified-deliverables witness; the maintenance survey classifies interrupted manifests by root liveness and proposes the machine-actionable next step (resume a live-root run, disposition a dead-root run once) instead of leaving the advisory perpetual; and backlog captures join the log's same-turn commit rule so a killed session strands nothing finished and uncommitted.

Witnesses: interrupted manifest 20260929T023532Z-3fb1c11bb98b (bound to a deleted worktree root; refused by both adopt and finalize on 2026-09-29; its disposition lives only in a memory note, and the current machinery never surfaces it again because the detector root-filters dead-root records - this plan makes the incident machine-visible and machine-closable), the stranded-captures landing ee0b2e15 (two finished uncommitted backlog captures waited 13 hours for a human), and the origin's own triage against current bytes (no disposition path exists in the manifest machinery; the maintenance survey has no manifest-classification arm; the same-turn commit rule exists for the investigate log and the cluster annotations but not for backlog captures).

## Outcome + Gate delta

An interrupted done run whose boundary can never be adopted closes exactly once: the disposition operation verifies each owned deliverable through its set-specific resolution (refusing the closure when a resolution fails), stamps the manifest with a `dispositioned` record, and the interrupted-run detection - widened by this plan to surface dead-root unadoptable manifests that today are silently skipped by its root filter - stops treating dispositioned manifests as orphans, so the Step 0 report names the incident until it closes and never after. The maintenance survey sees every interrupted manifest classified by root liveness and proposes the next action through its existing proposal machinery instead of a human triaging from raw reports. A backlog capture is never the only copy of finished work: the capture write commits in the same turn, and a capture that cannot commit records a recovery note naming the file.

Gate delta: one new read-only sub-command and one new mutating sub-command in `scripts/done_sweep_gates_lib.py` (`list-interrupted-manifests`, `disposition-manifest`), one additive optional manifest record (`dispositioned`, schema unchanged) carried first-class on `RunManifest` with loader/writer mapping, a widened interrupted-run detection contract (dead-root unadoptable manifests surface; dispositioned records suppress) with the orphan-report consumer's dead-root line naming the disposition path, the lib's hermetic suite gaining the behavioral arms (refusal set, round trip, re-run reprint, zero-owned sets, listing visibility, detection arms), one new disposition paragraph beside the adoption boundary in `agents/skills/done/SKILL.md` plus one interrupted-run-report honoring sentence, one survey-classification bullet in `agents/skills/maintenance/SKILL.md`'s Step 1, and one same-turn commit duty pair in `agents/skills/receiving-review/SKILL.md`'s Backlog capture section; no schema version bump, no new writer class, no gate or protocol layer.

## Terms

- **Unadoptable manifest**: an interrupted run manifest (`complete` false, unadopted) whose recorded `repo_root` value matches neither arm of the lib's two-arm matcher `_repo_root_matches_value`, so the adoption boundary and the finalize identity check refuse it; the witnessed shape is a manifest bound to a worktree deleted before its closeout.
- **Disposition**: the sanctioned one-time closure of an unadoptable manifest: the `disposition-manifest` operation verifies the manifest's owned deliverables through their set-specific resolution (the Deliverables witness), then stamps a `dispositioned` record; a dispositioned manifest is no longer an orphan and is never re-reported as interrupted.
- **Root liveness**: whether the manifest's recorded `repo_root` value matches the current repository root through the lib's two-arm matcher `_repo_root_matches_value` (a 64-hex digest compares against the current digest; any other value is a legacy raw path compared by realpath) - match means live, no-match means dead; digest-only comparison misclassifies legacy raw-path records.
- **Deliverables witness**: the disposition operation's verification that every path in the manifest's owned sets (`owned_plan_paths`, `owned_review_paths`, `owned_paths`, the `RunManifest` serialized key names) resolves against the landed work by set: an owned plan passes at its recorded path or its `plans_completed` archive twin at HEAD; an owned review passes against the docs branch (`git cat-file -e docs:<path>`; review staging docs are gitignored on the default branch); an owned path passes at `HEAD:<path>`; a missing deliverable refuses the disposition with the path named.

## Assumptions

- assume the disposition operation refuses a live-root manifest (the recorded root matches the current root through either matcher arm): a live root belongs to the adoption boundary or the resume arm, never to a disposition; basis: the origin's D arm assigns dispositions to dead roots only, and the adoption boundary already owns live-root continuation.
- assume the manifest schema version stays unchanged: the `dispositioned` record is an additive optional key and the loader's tolerant parse treats its absence as not-dispositioned; Task 1's carrier checkbox makes the field first-class on `RunManifest` (dataclass field, `as_dict` emission, tolerant `from_dict` mapping) so the value survives reload.
- assume the orphan detection widens to surface dead-root unadoptable manifests (today they are silently skipped by the root filter, which is why the witness incident was never machine-visible) and the dispositioned record joins adoption as the second suppression shape; basis: live probe of `_detect_interrupted_runs` against the checkout's manifests (the witness manifest is absent from detection today) and the detection docstring's suppression sentence.
- assume the survey bullet names no state-file field literally that the pins suite's per-bullet accounting constrains: the bullet routes proposals through the survey's existing proposal machinery (`park_proposals`/`pending_dispatch` are already read in the Step 1 region) and avoids the `pending_rearm` token, whose in-region occurrences the pins suite scopes to two named bullets.
- assume the same-turn capture duty is prose (no new state file, no gate): the investigate log's standing rule is the precedent, and the recovery note is a recorded line in the turn output or session notes, not a new artifact.
- assume idea A (closeout-before-teardown gate) rides the open family item `docs/history/backlog/2026-09-28-worktree-closeout-baseline-capture.md`, idea F rides `docs/history/backlog/2026-09-28-done-lock-one-shot-reclaim-releases-documentation.md`, and idea C (done-tail resume watcher) stays deferred until a fresh witness: the origin names all three as lower value than B, D, E, and each of A and F already has its own open item; basis: the origin's Suggested fix ordering and the two family items' presence at the top level.
