## Outcome

Make the execute-plan seed, readiness, preflight, and prelaunch recovery contracts agree so an incompatible seeded task contract fails closed at its earliest boundary or recovers through one sanctioned driver transition.

- A criterion that exceeds the runtime evidence limits is refused at the create boundary with the task and criterion named and an actionable split correction, never as an unnamed ValueError after the claim exists.
- A task's `Files:` declaration decides the same way in pre-round readiness and runtime preflight, including planned-new and indented entries; duplicate, case-variant, and ambiguous declarations are refused with named problems on both surfaces.
- A claimed prelaunch task holding a stranded evidence contract recovers through one locked, receipt-fenced driver operation that returns the task to a preflight-passable state, is replay-safe, refuses healthy or launched states, and leaves the manifest byte-identical on every refusal; multi-strand legacy manifests recover task by task with remaining strands named, never crashed on.
- The nine-case regression matrix plus intactness witnesses keep the launched-hold recovery, legacy digest compatibility, and task-local verifier requirements untouched; the reviewed-scope recovery stays a non-interference boundary verified by the composition-routing record.

## Terms

- **Prelaunch claim**: a claim whose state is `claimed` with no launch record, no active capacity reservation, no worker row, and no owning claim group in any state; the PROJ-607 stranded state.
- **Stranded contract**: a task's seeded evidence criteria that the runtime's limit checks refuse (the oversized-criterion shape); the only admission trigger for the prelaunch recovery. A declaration the documented grammar refuses while the criteria stay within the limits is a named residual, not an admission trigger; its exit is the skill-gated plan edit followed by preflight, which compares plan tokens against the seeded scope without needing claim rotation.
- **Corrected contract**: the replacement task evidence fields a recovery request supplies, exactly the task's `required_criteria` and `verification_commands`, validated through the rule set enumerated in Task 3's precondition phase (envelope, limit checks, pre-seed consistency, declaration grammar); no other field is accepted from the payload.
- **Planned-new marker**: the plans template's `*(new)*` annotation family on a not-yet-created `Files:` entry (the `*(new` prefix with optional elaboration before the closer); it records creation intent, and it must decide the same way in pre-round readiness and runtime parsing.
- **Evidence contract identity**: the manifest's `evidence_contract_digest` plus the per-task criterion ID map; what a recovery receipt binds as the corrected contract identity. A recovery receipt's prior contract identity binds the recorded `evidence_contract_digest` when the landed helpers can verify it against the task's stored evidence fields; when they cannot (the stranded oversized shape), it binds a raw identity instead: sha256 over the canonical JSON of the stranded task's evidence fields.
- **Replay fence**: the history-event-first precondition order that refuses a repeated recovery request by naming its already-recorded receipt.
- **Sibling strand**: another task's evidence fields that still fail the limit checks on a multi-strand legacy manifest; reported as named remaining work, never attributed to the corrected contract and never a refusal of the corrected task's recovery.
- **Scope refresh**: the reviewed-scope-recovery sibling plan's operation for a legitimate reviewed scope change; composition boundary, not a member of this plan.

## Gist & Examples

TLDR: one `Files:` declaration contract across pre-round readiness and runtime parsing, named seed-time evidence errors, and a receipt-fenced prelaunch contract recovery replace the divergent parsers and unnamed ValueErrors that stranded PROJ-607, closing the reliability gap the two origins witnessed.

Today the boundaries disagree. `plan_readiness.py --pre-round` requires the planned-new marker on a not-yet-created path, while the runtime's `_plan_declared_files` entry grammar rejects the annotation, so the same declaration passes one gate and fails the other; a duplicated or ambiguous declaration is union-collected by the readiness collector and silently narrowed to the first list by the runtime parser. Evidence criteria over 512 UTF-8 bytes die inside `create_manifest`'s eager evidence build (the contract digest computation first, then the criterion map) as a bare `evidence criterion exceeds UTF-8 item byte limit` ValueError that names no task and no criterion; the origin's witnessed run instead stranded after claim, with the documented `recover-evidence-contract` path covering only the launched hold and no sanctioned transition for the claimed prelaunch state.

After this plan: the entry grammar is one documented contract, so `- `src/new.py` *(new)*` decides the same way in both surfaces, a second `Files:` heading or a lookalike pseudo-heading refuses with a named problem on both surfaces. The create boundary refuses an oversized criterion with the task id, the criterion, its byte count, and the split rule. A PROJ-607-shaped stranded claim recovers through the new driver operation: the operator corrects the plan through the skill-gated plan edit, supplies the corrected contract with the plan path, and the transition closes the stale claim, returns the task to pending under the corrected evidence contract, and records one fenced receipt binding the prior and corrected contract identities; sibling strands on the same manifest are named as remaining work, and each subsequent claimed strand heals through its own recovery request.

## Design Invariants (CR Guard)

- `_plan_declared_files` remains the sole runtime declaration-parsing source: no second parser and no parallel declaration reader, mirroring the reviewed-scope-recovery reuse rule. Pre-round readiness keeps its own authoring-side record check, aligned to the same documented entry grammar, amended in place; that authoring-side check is the sanctioned second grammar consumer and is exempt from the single-parser census.
- Direct `runtime_state.json` edits stay prohibited; the new operation is the only sanctioned transition for a claimed prelaunch contract, exactly as the launched-hold recovery is the only sanctioned exit from that hold.
- Evidence limits (512 UTF-8 bytes per criterion, 4096 UTF-8 bytes aggregate, 100 criteria) are never raised or made advisory without consumer proof, and the limit checks stay single-homed in scripts/runtime_capabilities.py; consumers catch and attribute, never re-implement.
- Launched `recover-evidence-contract` semantics, the done-pending recovery disposition set, legacy evidence-contract digest acceptance, and task-local verifier pre-seed consistency stay intact.
- Every recovery refusal leaves the manifest byte-identical: fail-closed as a decision, never a partial write. Sibling strands inside a multi-strand manifest are success-evidence naming remaining work, never a raise inside the locked save and never a refusal of the corrected task.
- Prescribed insertions into the shared execute-plan skill body must pass `test_shared_skill_bodies_remain_runtime_neutral`; the Validation Commands block runs that test itself.
