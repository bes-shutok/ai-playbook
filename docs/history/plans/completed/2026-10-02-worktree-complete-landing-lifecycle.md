## Terminology and core concepts

- **Worktree-complete landing**: the landing lifecycle (the rebase onto the current base tip, the squash merge, the landing commit) executes inside the execution or authoring worktree; the primary checkout receives only the final squash commit through one ref update, and its index and working tree are never written by a landing.
- **Compare-and-swap ref update**: the `git update-ref refs/heads/<default> <new> <old>` form that lands only when the tip still equals the captured old value and refuses on any movement; the primary checkout's only landing touch.
- **Landing-gate violation (primary-checkout staging)**: staging (`git add`) in the primary checkout during a landing; a violation for every lane, refused before any staging.
- **Reconcile receipt**: the recorded exit code and row summary of `scripts/reconcile_post_landing.py` against the primary checkout; a closeout with no recorded receipt is a failed closeout, while exit 1 with every block row recorded stays the sanctioned partial state.
- **Session-owned fresh write**: a candidate path the session itself wrote during this run, listed in the freshness gate's fresh-write list, exempt from the disk-equals-HEAD requirement.
- **rc unmasking**: every landing shell pipeline checks and propagates rebase and merge exit codes; a masked failure aborts the landing before any staging or ref move.

## Evaluation Criteria

- The landing blueprint and both maintenance blueprint landing tails direct the rebase and the squash merge to execute inside the run worktree, and the primary checkout receives only the final squash commit through one compare-and-swap ref update.
- Staging (`git add`) in the primary checkout during a landing is named a landing-gate violation in the canonical standard, both blueprint tails, the D1 landing-completion arm, and the overlay mirror.
- The landing closeout records the reconcile receipt; a skipped or failed reconcile fails the closeout; the existing named-block protocol stays the sanctioned partial state.
- The pre-stage freshness gate exists beside `scripts/landing_parentage_gate.py`, refuses naming the paths when disk bytes match neither HEAD nor a session-owned fresh write, and every residual staging site wires it before the add, deferring on a refusal, never staging.
- Every landing pipeline checks and propagates rebase and merge exit codes, and a masked failure aborts the landing before any staging or ref move.
- `bash scripts/check_maintenance_pins.sh` exits 0 with the three affected literals re-keyed in the same tasks that remove their text, per the suite's freeze-literal convention, and the rewritten blueprint and D1 spans carry their dated deviation-list and Revisions-ledger registrations.

CLI contract (exit 0 pass, 1 refuse, 2 tool failure, mirroring the landing parentage gate's guard-family contract; the gate is read-only and never stages, restores, or writes):

- `check --repo ROOT [--head REF] [--fresh-list FILE] -- PATH...`: resolves HEAD (default `HEAD`) as a commit via `git -C ROOT rev-parse --verify <ref>^{commit}`; an unresolvable head is exit 2 with `prestage-freshness-gate tool failure: head unresolvable: <ref>` on stderr. For each PATH (repo-relative): read the disk blob with `git hash-object` over the path's on-disk bytes (a path absent from disk has no disk blob) and the HEAD blob with `git rev-parse --verify <head-sha>:<path>` (a path absent from HEAD has no HEAD blob). A path passes fresh when both blobs exist and are equal; it also passes when it is listed in `--fresh-list` (a session-owned fresh write; one path per line, `#` comments allowed). Otherwise it is refused with one line naming the path: when the disk blob equals the path's blob at some ancestor commit (the stale-checkout discriminator's walk over `git log --format=%H -- <path>`, skipping commits where the path does not exist, never treating a plumbing miss as a tool failure), print `refuse: <path> disk bytes equal ancestor <sha>, not HEAD <head-sha>`; otherwise print `refuse: <path> disk bytes match neither HEAD nor the session-owned fresh list`. Passing paths print `ok: <path>`; on full pass print `ok: all candidate paths fresh against HEAD` and exit 0; any refusal exits 1 with every offending path named; a git plumbing failure other than the expected absent-object cases is exit 2.
