## Terms

- **Execution lane**: the maintenance scheduler's plan-execution lane (`G1e` guard, D1 decision, execution children).
- **Dispatch carrier**: the mechanism that carries a decided dispatch out of the deciding turn: the clocked child (a one-shot automation via the create primitive), the idle-time primitive (`OffPeakCreate`), the in-session dispatch mode (the deciding turn runs the blueprint payload itself), or the parked `pending_dispatch` record.
- **Ladder precheck**: the runtime overlay's pre-ladder assertion that the session's toolset exposes the mutating primitives the decided dispatch needs (agents/skills/maintenance/zcode.md, "Child dispatch ladder", Ladder precheck).
- **Park-with-carrier**: the pairing duty that gives a parked dispatch an armed out-of-session resume carrier (the overlay's Launchd resume carrier recipe) so a parked queue is never carrier-less.
- **`authoring_cycle_gate`**: the new additive scheduler-state field arming the durable pacing gate between user-paced cycles (Task 2).
- **EXECUTION CLAIM**: the execution child's claim-file duty paragraph, the procedure of record at agents/skills/maintenance/prompt-templates.md (refresh triggers densified by Task 3).
- **Execution manifest**: the execute-plan run manifest (`manifest.md` plus machine `runtime_state.json`: workflow_state, task checkboxes, execution record); the resume source of truth for boundary compaction.
- **Pins suite**: `scripts/check_maintenance_pins.sh`, the mechanical span-presence/absence suite gating the maintenance and execute-plan skill surfaces.

## Gist & Examples

TLDR: the execution lane gains a clocked, then idle, then in-session, then park-with-carrier carrier ordering, execute-plan runs compact at green task boundaries, and user-paced cycles gain a durable continuation gate, so reduced-toolset turns and long sessions can no longer park a ready queue or lose durable state (new-capability + efficiency).

**Before (today), scenario 1 (the HIGH origin's witness).** The 2026-09-26 04:0x automation-born scheduler turn holds a reduced toolset: no create/update/delete automation primitives. The execution queue head is a certified, digest-intact plan; quota sits at 3 percent used with 286 minutes to reset; no lane competes. The turn walks the ladder precheck: the clocked leg needs the create primitive (absent), the idle leg needs `OffPeakCreate` (the only lawful execution carriers are clocked and idle), and even when the idle primitive exists the queue head it could carry is a same-turn decision, not a decided park. The lane parks bare (`pending_dispatch` with reason "turn toolset lacks CronCreate"), the re-arm leg also lacks its primitives, so the loop goes dark and the certified queue idles until an external touch. The park is correct under current rules; the rules are the defect: the authoring lane solved this same problem on 2026-09-20 with the in-session dispatch mode, and the execution lane never received the equivalent.

**After (this plan), scenario 1.** The same turn walks the new Execution-lane carrier-selection ordering in fixed order: the clocked leg is retired by the precheck (no create primitive); the idle leg dispatches through `OffPeakCreate` when the session owns it (out-of-session delivery, the existing idle-child lane-hold, idle-listing attribution, and failure-cap coverage apply unchanged); when the idle leg is unavailable too and the quota signal is abundant, the in-session leg runs the execution blueprint's payload in the deciding turn itself, recording the standard `(in-session)` children[] entry with `dispatch_plan_sha` and `quota_signal`; when no dispatch leg is available, the lane parks and the park pairs with the launchd resume carrier, so the parked queue is never carrier-less. Every leg taken is recorded in `decision_reason.execution`, and pins cover the ordering so the retired absolute wordings (never routed in-session, never idle-dispatched) cannot silently return.

**Before (today), scenario 2 (the compaction origin's witness).** An interactive execution session runs its context to exhaustion mid-turn; the harness summarizes and the continuation re-reads files and re-derives state (validation paths, lock-token handling) that a durable checkpoint would have preserved. Compaction today fires only at the blueprint's FINAL STEP (after the report) or at the 85 percent measurement rung, never proactively at the boundary where all state is already durable.

**After (this plan), scenario 2.** At every green task boundary (Step 1.4 verification gate passed: commit landed, manifest updated), with plan work remaining, the run compacts at the boundary via the runtime compaction primitive when one exists; on a runtime without one the boundary report carries the no-primitive note and the run continues. The manifest (workflow_state, task checkboxes, execution record) is the resume source of truth, never the transcript summary. The duty never fires mid-task, inside a review round, or while a merge lock or landing critical section is held (the origin's non-goals).

**Before (today), scenario 3 (the cycle-gate origin's witness).** A session runs one-at-a-time authoring cycles under a user directive that gates each next cycle on a user-run compaction. Context hits the ceiling between cycles; the harness auto-compacts; the resumed turn cannot distinguish the auto path from a user compaction and walks straight into the next cycle's due checks. The user's intended pause point silently disappears.

**After (this plan), scenario 3.** A session closing a cycle under a standing user pacing directive arms `authoring_cycle_gate` in the scheduler state file (one targeted field edit). The resumed-turn rule (SKILL.md Cycle gate section, classified concretely in zcode.md): a continuation-summary resume that finds the gate armed performs due checks plus a readiness report and stops; only a real user message starts the next cycle and clears the gate (datable cleared trace, the loop_mode withdrawal precedent). An unattended scheduler turn finding the gate armed resolves the lanes to the sanctioned skip `cycle-gate-armed`, and a retained or parked dispatch target is held back for the same reason (the Step 1 reader retains it; the park-discharge duty does not discharge it), so the unattended loop cannot silently defeat the user's pacing gate on any dispatch path. A session running under no pacing directive never writes the field: unattended behavior is unchanged.

**Fold (the queue-drain-lows origin).** The execute-plan queue-drain paragraph presents its densified claim-refresh triggers (every task completion, every review-round iteration) under the name of the EXECUTION CLAIM paragraph, whose record carries only "refresh `updated:` at every phase boundary"; and it says "one-execution-child guard", which is not a corpus term of art (the asserted-unchanged family is `G1e` plus the P54 fleet cap).
