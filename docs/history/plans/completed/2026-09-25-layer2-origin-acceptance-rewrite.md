## Terms

- one-recipe rule: the doc-hierarchy Layer 2 placement decision (`doc-hierarchy` company-decisions, Locations) that disposable Compose/JAR recipes, smoke curls, and local escape hatches live only in `docs/maintenance/local-development.md` (or the service equivalent), production/UAT release checks and runtime tunables live only in `docs/architecture/operational-guides.md`, and the ops file keeps at most a one-line pointer to the local guide; encoded author-side by `doc-hierarchy-upkeep` Step 4 and review-side by the `review-plan` Step 1 plan-closure matrix bullet.
- origin acceptance: the acceptance or expected-behavior text of a backlog item being promoted to a plan.
- stale acceptance: origin acceptance that encodes a superseded placement or process, such as asking to document local enablement in the ops guide.
- dual-recipe witness probe: the guarded two-line check pinned in Task 2; run under bash at a service-repo root, it intersects the column-0 fenced code blocks of that repo's `operational-guides.md` and `local-development.md` and greps the intersection for `java -jar` and `docker compose`; exit 0 with output lines means recipe lines shared between the column-0 fenced blocks of both files (inspect the lines before building the verify-family assertion), exit 1 means no shared recipe-shaped (java/compose) lines among column-0 fenced blocks (list-indented fences are invisible to it), exit 2 means a target doc is missing or unreadable (the probe witnesses nothing); the guard exits the calling shell by design, so save the probe as a file or wrap it in ( ... ) before running; an unbalanced or mixed-indent fence run can corrupt the capture window and a directory at either path also reports as exit 1, so investigate before trusting clean.
- verify family: the `doc-hierarchy-migrate` verify script (`agents/skills/doc-hierarchy-migrate/scripts/verify-doc-hierarchy.sh`), where the origin item's conditional assertion would live if its trigger is ever met.
