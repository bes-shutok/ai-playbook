# Sequential landing discipline: never dispatch a new execution/authoring before the previous run's squash merge lands
Status: done (executed via docs/plans/completed/2026-09-22-sequential-landing-discipline-no-dispatch-before-squash.md)
Disposition: 2026-09-24 (routed via docs/plans/2026-09-24-closure-strays-disposition-routing.md, Task 5): the namesake plan executed on main at 206a7f7b and all five requested clauses are landed: the successor-dispatch landing gate chain-nothing conjuncts (prompt-templates.md), the D1 pre-dispatch landing gate on both lanes with the landing read-back and landing-completion resolution (SKILL.md), the authoring mirror (authoring-lane D1 conjunct plus the self-landing landing-intent record duty), the fleet rule capping the post-review pre-landed state at one recorded run with zero outstanding unlanded runs per dispatch (SKILL.md invariants), and teardown gated on the verified landing.

Driving force: on 2026-09-21 the execution-only chain produced two executions whose squash merges to main were separately deferred or raced peer work in the primary checkout (the durability plan's merge --squash aborted on peer dirt overlapping branch files, and was only landed hours later by explicit operator instruction). Nothing in the maintenance skill (SKILL.md Steps 3/5, the runtime overlay's dispatch ladder, or the execution blueprint's SUCCESSOR DISPATCH duty) gates the NEXT dispatch on the PREVIOUS run's landing: a completing child chains a successor, and a scheduler turn's D1 dispatches, without checking that the just-finished run's squash actually landed on main. A failed or deferred merge therefore leaves the plan executed-but-unlanded while the queue moves on: stranding work and stacking merge collisions. Status: open.

Requested change (maintenance skill + overlay + blueprints, one coherent gate):
- A completing execution child's successor-dispatch duty (prompt-templates.md) gains a LANDING GATE as a chain-nothing condition: after the final squash merge attempt, verify the landed commit on main (the squashed subject is present at main's tip, or the branch/worktree still exist when the merge was deferred); when the landing did not happen, chain nothing, record the deferred landing in the session manifest and a repo-keyed memory note (e.g. `pending-landing`, carrying the branch name, worktree path, and plan slug), and end. The successor target is then dispatched by the next scheduler turn only after the landing is confirmed or completed.
- The scheduler turn's Step 3 D1 (and the Step 1 survey) gains a pre-dispatch landing check: any pending landing note (or a non-archived plan whose execute-plan manifest reads workflow_state complete without a landed squash) blocks the next execution dispatch; D1 resolves to the landing-completion work first: retry the squash from the primary checkout (including the sanctioned stash-and-restore of overlapping peer dirt, as operator-authorized 2026-09-21), or, when the primary checkout is still occupied by live peer work, defer with decision_reason `pending-landing (primary occupied by peer session)` and retry next turn.
- The authoring lane mirrors the rule for its own landings (an authoring child's self-landing step must verify the landed commit before the session ends; a failed landing is recorded the same way).
- Fleet rule to encode in SKILL.md's invariants: at most one execution (or authoring) run may be in the post-review, pre-landed state at a time; a new child dispatch of the same lane requires zero outstanding unlanded runs for that lane.
- Teardown stays gated on the landing: the branch+worktree deletion and docs/reviews migration may proceed (artifacts are landing-independent), but the memory note and any pending_dispatch park clear only when main carries the landed squash.

Source: operator directive 2026-09-21 ("we should never start a new execution (or plan authoring) until we successfully squash merged the last one. If something is blocking we should either fix the block or schedule retry if fixing is not feasible or this is a temporary block from other session").
