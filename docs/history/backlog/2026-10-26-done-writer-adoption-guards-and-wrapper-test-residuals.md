# Backlog: done writer adoption lacks an owned-foreign intersection guard and an adopted-set check; wrapper test helpers duplicated

- Status: open
- Priority: medium
- Age: new (2026-10-26)
- Cluster: docs/history/plans/completed/2026-10-25-done-run-resume-ownership-gap.md (the wrapper-side adoption route this row's writer-side residuals sit beneath)

Driving force: reliability (witnessed by the 2026-10-26 done-run-resume-ownership-gap execution run, Phase 3 round 1 risk and design lenses)

`write-manifest --adopt` in `scripts/done_sweep_gates_lib.py` validates root identity, completion state, and start-commit resolvability only. Two residuals the wrapper fix deliberately left at the writer (the plan scoped lower-level adoption behaviour out): (1) the adopt arm merges `--owned-review` claims and the adopted record's `foreign_review_paths` with no intersection refusal, so an adopter can name a path the prior record marked foreign and the commit-time foreign-staging gate, reading owned first, treats it as owned (verified in a scratch repo: one path landed in both lists); repair with a writer-side refusal, or foreign precedence, when a claimed owned review path resolves into the adopted record's foreign set. (2) the writer never checks whether the target run id is already in the session's adopted set and takes no lock, so a direct writer invocation can adopt the same orphan twice or adopt a live boundary; the wrapper's classify-time refusal covers only the wrapper path; repair with one refusal when `candidate.run_id` is in the adopted set `_detect_interrupted_runs` already computes. Round 2 extension (risk and correctness lenses, witnessed by scratch-fixture probes through the wrapper's terminal-newest forward arm, done_run.sh:296-301): the adopted-set predicate alone is insufficient: the forward arm also accepts a target whose boundary a disposition record already closed (the writer reads only the canonical manifest, never the disposition, and the lib's own usage text calls a dispositioned record unadoptable), and closure carried by a non-canonical manifest copy is likewise invisible; repair with a run-identity verdict check instead (refuse when `classify_run_boundary` on the candidate names anything but an interrupted orphan, which subsumes the adopted-set case), and pin the already-adopted-behind-terminal-newest and dispositioned-target forward-arm shapes with regressions. Test-side residuals from the same round: `DoneRunSetupAdoptionTest` hand-rolls the manifest copy/rewrite and session-listing helpers that `DoneRunSetupManifestStateTest` already carries (promote `rewrite_manifest`, `craft_manifest_file`, `session_names` to `FixtureMixin`); and the plan's Gate delta sentence names two message variants of the mixed-input class while the wrapper also refuses two adopt-target shapes (mismatched orphan id, classified terminal id), a wording gap the archived plan carries as-is.
