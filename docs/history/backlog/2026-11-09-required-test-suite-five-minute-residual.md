## Externally killed worker containment (unverified)

The runner's worker cleanup runs on normal return and catchable exceptional exits, but cannot run after an external `SIGKILL`. A detached child can outlive the worker and be reparented before the parent runner's later process-group snapshot, so the parent may no longer have a reliable attribution path. Do not claim the current cleanup contract covers this case. In the next lifecycle investigation, include a worker externally killed while it owns a detached child; compare macOS and CI containment mechanisms and verify whether the child is contained or reliably attributable after reparenting. Record the exact kill, containment and cleanup outcomes. This is an open reliability boundary, not a reason to weaken test accounting or add an unreviewed runtime gate.
