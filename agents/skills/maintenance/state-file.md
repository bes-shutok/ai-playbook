`alert` is `null` or an object `{"tripped_at": "<iso>", "reason": "<short reason>"}`.

`turn_error` is `null` or a short reason string; a fully successful turn resets it to null.

`rearm_note` is `null` or a record of a refused parent re-arm or a dispatch-direction conflict, naming the refusal or the conflict in the writer's own words, except that a structured refusal note (the Step 1 reader refusal record and the Duplicate-parent migration arm's bound records) opens with the live-bound condition's structured first line (a reason string such as `armed-child-record-conflict` is a `turn_error` value, never a `rearm_note` value). Writers: the child's re-arm duty on a refusal, a turn's loop guard, a turn's hand-off refusal record, a turn's Step 1 reader on a refused re-arm create, a rearm-on-touch session's loop guard, the watchdog's level-2 escalation, and the Duplicate-parent migration arm (its three bound records: a precheck-absent leg, a refused delete leg, and a refused or post-route-unverifiable retitle or re-create; each note opening with the structured first line, the id field carrying the targeted old-form record's id). Clearers: every listing-derived armed-observation clear (a turn's Step 0 check listing, a turn's Step 2 guard listings, a rearm-on-touch session's armed-again observation alike) skips a note carrying a live bound's structured first line, so no clear can erase an active bound's witness, and the witness ages out with its cadence period, after which the clear applies normally; the clearers are the child in the same targeted edit when its re-arm later succeeds, a turn on any listing-derived observation of an armed parent (the Step 0 check's listing or the Step 2 guard listings the turn already performs), the watchdog on its recovery re-arm, a rearm-on-touch session whose recipe re-arm succeeds, a turn whose Step 1 pending_rearm reader re-arm succeeds (the mechanical re-arm's clear, beside its `pending_rearm` clear in the same targeted edit), and a rearm-on-touch session on any listing-derived observation of an armed parent (the armed-again clear, no longer bound to the state-first cannot-decide listing alone).

`pricing_cache` is the turn-owned usage-pricing cache (window, multipliers, verification date, source); it wins over the runtime overlay's tracked seed when its `last_verified` is fresher, and only the cache is updated by a turn (the tracked seed is re-pinned by a human; see the overlay's Quota leg).

`parent_automation_id` is the loop carrier automation's id (the chained one-shot or the recurring fallback record; the form is the cadence rule's), filled at initialization with the carrier's automation id (`null` when unknown); a scheduler turn never treats its own parent as a lane occupant. Exclusion, fallback, and self-heal semantics are stated once in the widened arm and the duplicate-parent tripwire (Step 2), not restated here.

`parent_absent_since` is set when the absence is first observed: the transition from a listing that showed an ENABLED recognition match (or from a null field) to a listing that shows none writes that observation's timestamp, and while the absence persists the field keeps the earliest value and is never refreshed to a later observation's timestamp. Only a listing showing an ENABLED recognition match clears it. Absence with a pending child entry carrying `parent_automation_id` is expected surrender (record oscillation child form). A pending child entry explains the absence only while it is live, meaning its `fire_at` (or `created_at` for idle-time) is fewer than six hours past with no failed outcome: a ghost pending record past that horizon does not suppress the darkness classification, mirroring the human check's six-hour rule, so a never-fired record cannot silence automated finders indefinitely. Absence with no live pending child and `parent_absent_since` older than one cadence period (2 hours) is darkness, and an automated finder (turn Step 0 or a rearm-on-touch session) re-arms per the overlay recipe instead of only noting. With the carrier armed per the cadence rule, the armed chain record sitting ENABLED between turns is the expected inter-turn state, not darkness: its recognition match clears `parent_absent_since` on any touch during the gap, so the absence clock never starts while the carrier is armed.

`next_turn_at` is the armed carrier's fire time: when the loop carrier is armed, the time it next fires; `null` when nothing was armed. Writers: the Turn-start carrier re-arm duty (its final targeted edit records the fresh carrier id into `parent_automation_id` and the armed fire time into `next_turn_at` in one edit) and the child re-arm duty's final targeted edit (the same one-edit recording when the child restores the carrier per the cadence rule, so the field never goes stale during the routine past-reset gaps an armed chain record spans); the Step 6 rewrite carries the field forward beside the other externally written values. The field is additive under schema 4 (no version bump).

`parent_automation_form` is the armed carrier's form: `one-shot` or `recurring` when armed; `null` at rest. Writers: the Turn-start carrier re-arm duty and a rearm-on-touch session's arming edit record it beside the id, and the Step 1 reader's id-adoption edit clears it to null; the read keys on the form recorded beside the currently recorded `parent_automation_id`, and any other case (a null field, an unrecognized value, an id adopted without a form, or a recognized non-null form recorded beside a different id than the arming edit recorded, the stale-form case) is form-unknown. A form read is valid only beside the id the arming edit recorded; a stale form left by a non-form-writing id write such as the watchdog recovery re-arm or the child re-arm duty's targeted edit reads as form-unknown. (an additive field; schema version unchanged).


`pending_dispatch` is an object `{"kind": "execute|author|audit|retriage", "target": "<path>", "payload_slug": "<blueprint id>", "decided_at": "<iso>"}` or null; written by a turn that decided but could not schedule, by a completing execution child's successor duty on its both-legs-fail branch (the parked successor target), and by the audit lane's park write when its consult reads due while the authoring lane holds (the registry consult's park arbitration); read at Step 1. The payload_slug is informational only; the Step 1 reader dispatches by kind and target. The entry carries an additive optional `note` member (added 2026-10-08, the audit-lane-slot-take-unblock plan Task 1): free-form state such as retained-refusal evidence (the host message and the quota slug), written under the section's additive-field pattern with no version bump; readers that do not know the member ignore it. The kind enum never gains the ad-hoc kind (added 2026-10-06, the two-mode loop policy plan Task 3): blocked ad-hoc work holds with a recorded reason and never parks.

`execution_queue` is the ordered array of executable plan paths (dependency-chain and priority ordering applied; popped at the head on dispatch), an additive field under schema 4 (no version bump); written by scheduler turns (the D1 selection's head pop and the queue's assembly writes, each pop recorded in `decision_reason`) and by execution children (the successor-dispatch class's queue-prepend write: a finishing child prepends the next selected target to `execution_queue` in the same targeted edit family as its successor dispatch); an invalid head pops and the next head is evaluated, each pop recorded; the Step 6 rewrite carries the field forward.

`execution_priority` is the standing user ordering directive: an additive field under schema 4 (no version bump), an object or null, `{"directive": "<user wording>", "set_at": "<iso>", "note": "<carrier instructions>"}`; written by a turn or session carrying an explicit user ordering directive, replaced or withdrawn by the same writer; a withdrawal leaves the datable `cleared_at` trace like `authoring_cycle_gate` (the withdrawal writes the cleared field with a null directive plus `cleared_at: <iso>` in the same targeted state edit, never a plain null); when set, D1's ordering reads it before the memory dependency-chain order.

parked_dependencies is the ordered array of parked-dependency ledger entries: an additive field under schema 4 (no version bump); each entry is an object `{"plan", "blocked_on", "since", "boundary_arm"}` plus four optional keys: `deferred_until` (ISO 8601; set by a gate-refusal deferral, honored by the survey arm's actionable proposal and D1's unblock selection), `refusal_count` and `refused_tip` (the consecutive refused unblock attempts and the resolving-ref tip sha at the last refusal; the survey arm resets the count when the tip differs), and `landed_as` (the squash commit sha the unblock child records in its own targeted edit at verified landing, BEFORE the separate clear edit, so the sha is durably observable and the resolution probe's ancestry arm can fire on a lost clear write); `plan` is the resolved plans_dir-relative plan path, `blocked_on` is the BARE ref name as a probe namespace prefix consumes it (a local branch name like `main`, or a remote-qualified name like `origin/foo`), `since` is the ISO 8601 wait start, and `boundary_arm` is the task or gate identifier that recorded the wait. Writes are idempotent per (plan, blocked_on) pair with earliest `since` retention on re-record (the `parent_absent_since` earliest-value precedent). Writers: the execute-plan serialization-boundary write (written by the ending run, dispatched or interactive alike), the unblock child's clear-on-landing write, the unblock deferral's entry update (setting `deferred_until`, `refusal_count`, and `refused_tip`; the unblock gate-refusal deferral carrier is the child's own `children[]` entry outcome write, an existing sanctioned class, and the entry update joins the clear-on-landing class as its own targeted entry edit), and the survey liveness arm's clear and reset writes. Clear arms: the entry's plan absent from the top-level plans survey as parked, completed, or archived; or the branch probes showing the wait resolved, meaning zero commits ahead on the resolving ref, or the recorded `landed_as` squash commit now an ancestor of the default branch, or the name unresolvable in both ref namespaces with the plan otherwise dispatchable.


`authoring_cycle_gate` is the durable pacing gate between user-paced cycles: an additive field under schema 4 (no version bump), an object or null `{"gate": "awaiting-user-go", "directive": "<the pacing wording that armed it>", "set_at": "<iso>", "lane": "author|execute", "note": "<short reason>"}`. The gate is armed when the field is an object whose `gate` member is a non-null string; a cleared field (an object carrying `gate: null` plus a cleared timestamp) is not armed. Writer: a session closing an authoring or execution cycle while running under a standing user directive whose own text gates the next cycle on a user-side action (a compaction or explicit-go leg), via one targeted field edit in the same closeout pass, recorded as the sanctioned-writer enumeration's own cycle-gate write class (the eighth sanctioned writer class); a session running under no such pacing directive never writes the field (unattended loop behavior unchanged). Clearer: an explicit user directive in a later turn only, via the directive-write clause the scheduler-turn and rearm-on-touch classes carry (the clear is a directive-clause write, never a new class); the clear leaves the datable trace, the cleared field carrying `gate: null` plus `cleared_at: <iso>` (the cleared-trace precedent the `execution_priority` withdrawal shares). The field's object shape carries the additive optional key `cycles_completed` (integer; additive under schema 4, no version bump, the `cleared_at` precedent): the pacing cycle count, incremented by the cycle-gate write class's closeout targeted edit beside the gate arm and firing only under that class's own writer condition (a standing directive whose text gates the next cycle on a user-side action); the increment is a targeted member edit preserving the other members, a cycle-start clear (an explicit user go directive clearing the gate) preserves the count, and the count drops only when the pacing directive itself is withdrawn (an explicit withdrawal record leaving the cleared trace, so a fresh pacing directive starts from zero); loops without a pacing leg carry no count, and the count's only reader is the Cycle gate section's readiness report, which the same condition gates. Readers: the Cycle gate section's resumed-turn rule, the Step 3 lane decisions, and the Step 1 dispatch paths (the pending-dispatch reader and the park-discharge duty); a turn finding the gate armed resolves the lanes to D3 with the reason `cycle-gate-armed` recorded in `decision_reason` as a sanctioned must-dispatch exemption, and a retained target is held back for the same reason, so the unattended loop cannot silently defeat a user pacing gate while the survey, the guards, the read-backs, and the state write all still run. The Step 6 rewrite carries the field forward.

`pending_rearm` is the re-arm intent record: an additive field under schema 4 (no version bump), an object or null, `{"decided_at": "<iso>", "source": "<writer>", "note": "<short reason>"}`. Writers: the child re-arm duty's escalation on a refused re-arm, the rearm loop guard's stand-down on a suppressed re-arm, and the idle-time watchdog escalation (a refused re-arm whose already-exists verification failed), each paired with the assembled parent payload copy under the rearm kind's identity-bound payload filename (derived per this paragraph's derivation below) in the same targeted state edit and BEFORE the corresponding memory note, so a writer session that dies leaves the decided re-arm mechanically executable; the duty's decision-first recording (the intent recorded before or with the listing that still remains when it has decided the create/adopt) writes the same paired record. The successor both-legs-fail branch is NOT a pending_rearm writer: it parks `pending_dispatch`, its own existing field.
