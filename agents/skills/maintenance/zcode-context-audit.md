## Context measurement primitive

Added 2026-09-19 (the context-budget plan). The checkpoint duty itself lives in the child blueprints (template-authoring.md and template-execution.md) and the ladder policy in execute-plan's `Context budget checkpoints` section; this section is the overlay's measurement half, naming what this runtime actually exposes.

- Stats surface: ZCode exposes no session-invokable context-stats primitive (verified 2026-09-20: no stats surface in the session toolset), so checkpoints measure with the char-count proxy below.
- Proxy locator (host-scoped, pinned): the persisted transcript events live in the SQLite session store `~/.zcode/cli/db/db.sqlite` (with its `-wal`/`-shm` siblings; verified 2026-09-20, store populated): the `message` table holds one row per persisted event keyed by `session_id`, payload in `data`, ordered by `sequence`; count the characters of the current session's `data` values (a `sqlite3 -readonly` sum of `length(data)` over `message WHERE session_id = <this session's sess id>`; the idle listing's session-identifier match in "Child dispatch ladder" is the precedent that a session recognizes its own id). Never commit the resolved absolute home path into the repo; the tilde form is the pinned locator literal, the same convention as the recipe's `{REPO_ROOT}`. The proxy counts the session's cumulative persisted transcript since session start: persisted rows are never deleted, so the est_ series reflects within-session growth only and never drops across a compaction.
- Proxy ratio: pinned at ~4 chars/token, and every telemetry record carrying it is labeled an estimate (the record's est_tokens_before / est_tokens_after fields take the est_ prefix for exactly this reason). The store's turn_usage table (verified 2026-09-23 per task notes) carries per-turn token columns, but none tracks context size via per-session sums (a per-row input_tokens value approximately tracks that single request's context, mostly cache-inflated), so the proxy stays the primary estimate and the est_ labeling remains load-bearing.
- Loud degrade: when no locator exists, or the located store is unexecutable (missing, unreadable, or the session id not resolvable), the checkpoint still lands: append the checkpoint record with `action: no-primitive` and continue. An unexecutable measurement must be visible in the telemetry corpus; a silently skipped checkpoint is a policy regression, not a save. This applies execute-plan's `Context budget checkpoints` degrade rule to this runtime; that section owns the rule.
- Compaction: ZCode exposes no session-invokable compaction primitive: see the "Child dispatch ladder" Session compaction bullet, the single living home for the user-side-command fact; do not duplicate it here. When the runtime cannot invoke a compaction primitive, compaction degrades to the manual template procedure prescribed in execute-plan's `Context budget checkpoints` section (the above-85% rung's handoff-document procedure).

## Audit recipe

Pointer stub (2026-10-03, recurring-task-registry plan Task 4): the friction-audit lane migrated to the recurring-task registry. The registry entry (the audit task `friction-audit`) is the procedure of record, and the task file under the resolved `recurring_tasks_dir` is the data map's home; the per-source watermark rules live in the task file body, the generalized `next_due` stamp rule remains in the SKILL.md registry consult bullet, and this overlay carries no second copy.

Maintenance-side memory writes are append-first one-line entries, pointer plus hook, roughly 200 characters per entry, added at the end of the index; a wholesale rewrite or reorder is never the write shape (the operator-approved memory-index consolidation run is the single sanctioned exception, chartered in `docs/maintenance/recurring-tasks/memory-index-audit.md`; its reviewed fold shapes, per-mandate summary lines included, are sanctioned targeted edits, and bulk means unreviewed mass retirement), while the sanctioned targeted edits (clearing a cleared record's note, refreshing a note's carried value, folding a superseded entry into its successor) stay targeted; conversation-scoped lane state is not durable memory; when in doubt, index rather than prune. Standing retirement rule (2026-11-05, the consolidation plan), the convention's complement:

- Supersession fold: a record superseding an entry's carried value folds the old line's still-durable signal into the successor or a per-mandate summary line in that same targeted edit.
- Deletion pairing: a change deleting a topic file removes every index line pointing at it in the same change.
- Reviewed shape: retirement is reviewed, never bulk; an entry in doubt stays (index-rather-than-prune).
- Live-marker refusal: a line whose live do-not-redo marker or standing preference a lane depends on never retires unless its durable signal is captured by the successor line or durable repository records.
- Write-time supersession: a record whose durable signal git-tracked surfaces (archived plans, git history) carry folds into a per-mandate summary line in that same would-be-recording targeted edit, or skips the append; it never adds a new line.
- Retirement pass: the memory-index-audit lane's threshold-gated retirement member applies this rule's fold shapes as sanctioned targeted edits; its threshold, record scope, and run guards live in that lane file.
- Fire-outcome fold: a fired run's outcome write folds its own pre-fire record line in that same targeted edit, so a pre-fire status phrase never survives its dispatch.

Terms: bulk is unreviewed mass retirement; a per-mandate summary line summarizes a completed maintenance mandate's durable outcome; a durable signal outlives its writing conversation; fuller definitions: the consolidation plan's archived Terms.
