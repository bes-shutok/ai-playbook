## Task-index fire ledger

Added 2026-11-06 (plan `docs/history/plans/2026-11-05-automation-fire-time-failure-verification.md` Task 1): the runtime's persisted fire ledger is the SQLite task-index store, the read source for the survey's warning-only post-fire verification arm (survey-arms.md Step 1). Resolution: the `ZCODE_DATA_BASE_DIR` environment variable's `v2/tasks-index.sqlite`, falling back to `~/.zcode/v2/tasks-index.sqlite` (the tilde form is the pinned locator literal, the same convention as the Context measurement primitive); open it read-only (`mode=ro`), never write it, and accept an explicit database path for fixtures. Observed schema (2026-11-06): the `automation_runs` table carries one row per fire keyed `run_id` (`<automation_id>:<scheduled_at ms>`) with `automation_id`, `workspace_key` (the absolute repository path), `scheduled_at`, `created_at`, and `updated_at` as epoch milliseconds, `trigger`, `dispatch_status` (`dispatched`, `failed_to_dispatch`, `skipped`), `outcome` (`succeeded`, `failed`, `running`, or empty), `session_id` (the fired session's id), `error`, and `attempts`. A session's terminal outcome lives in the run row's `outcome` value; the automation-record lifecycle fields the `CronList` listing exposes (`lifecycleStatus`, `enabled`, `nextRunAt`) are the record's own scheduling state and never substitute for the session outcome. The linked task row joins by `workspace_key` plus session id (`tasks.task_id` = the session id); its `meta_json` carries the structured `lastError.attribution` fields the arm may persist (`exceptionKind`, `reason`, `retryable`), while `lastError.message` and `.detail` (raw provider message, request ids, provider payload) are never persisted. Automation prompts live in the `automations` table (`prompt` by `automation_id` plus `workspace_key`), not in the run rows: a run whose automation record has aged out has no prompt, which is the overlap arm's `mandate_match=unknown` case. A missing database, table, or required columns reports unknown and writes nothing. `scripts/maintenance_fire_outcomes.py` is the read-only adapter owning this read path and the bounded state-note helper; live calls may rely on the resolver, fixtures pass explicit paths. Census receipt (added 2026-11-19, plan docs/history/plans/2026-11-14-post-fire-verification-arm-zero-executions.md Task 3): the census-relevant automations columns are recorded from read-only probes, the authoring probe 2026-11-14 and the execution-time re-probe 2026-11-19 reading the same columns: recurring INTEGER NOT NULL DEFAULT 1, enabled INTEGER, lifecycle_status TEXT NOT NULL DEFAULT 'active', next_run_at INTEGER; the census predicate reads recurring = 0 from this recorded schema surface.
