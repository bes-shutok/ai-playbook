### Step 4: quota leg

This leg binds every clocked child dispatch, from any session type: a scheduler turn, a pending_dispatch re-dispatch, a successor-chain dispatch, an operator-requested dispatch, and a resume continuation all apply it before creating the child; a dispatch path that cannot run the leg (no probe access) proceeds on the fallback without a state write; a sanctioned-writer decider records the fallback evidence on the child entry at its next Step 6 rewrite, and any other decider surfaces it in its own turn output. The leg's probe report is also the D2 primitive-choice input for the authoring lane (Step 3): its decision and used_percent decide whether the authoring work authors in-session or dispatches out, alongside this leg's existing fire-time role; the single report at one boundary is shared between the D2 primitive-choice input and the fire-time role, and the leg's probe economy is boundary-scoped, never once-per-turn: at a maintenance-owned boundary (a lane decision, a mandate pick, an EXEC-PROMPTS item transition) a deciding turn or execution child expects a fresh probe read before the work starts, a read taken since the previous boundary counts as fresh, a read older than one cadence period (2 hours) always re-runs the probe, and boundaries a budget gate already probes (authoring phases and review rounds, whose percent-and-minutes gates run their own probes) ride that gate's probe and add no second read, an ad-hoc dispatch boundary rides its lane decision's boundary read (the fourth class in this boundary enumeration), and a read from before the previous boundary is never fresh.

Quota signal definition (added 2026-09-21): the quota signal D2's carrier decision consumes (Step 3) is named by one slug; the slug vocabulary is probe-available, probe-scarce, probe-near-reset, probe-paused, rate-pressure-scarce, queue-refused, user-reported-available, user-reported-scarce, peak-window, unknown; the sources are the window probe's percent and minutes-to-reset when its output is usable, the idle-time dispatch primitive's refusal, the user's own report, and the state file's `rate_pressure` as a scarcity proxy, unknown otherwise; the rule's peak-priced wording maps to the peak-window slug, whose named producer is the pricing calendar (the `pricing_cache` peak window, when the proposed carrier's run would start into or straddle it), and probe scarcity readings between available and near-reset map to probe-scarce. The probe read at the D2 carrier decision reuses the boundary's fresh probe read per the cadence duty in the leg's opening paragraph (no new primitive; a stale read never serves a boundary). Precedence for conflicting sources at one decision: the dispatch-primitive refusal outranks the probe reading (it concerns the carrier path itself and is the most recent host-surfaced fact), a user report given at or after the probe read outranks the probe, otherwise the probe outranks the `rate_pressure` proxy, and unknown is recorded only when no source is readable. Every carrier-bearing authoring decision record (a dispatch, an in-session pivot, or a quota-citing no-op; guard-tripped stand-down no-ops excluded) must name the observed signal as the literal token `quota_signal=` followed by one slug inside decision_reason.authoring (for example "authoring": "dispatch target X; quota_signal=probe-available; carrier: in-session"), so a carrier-bearing record omitting the token is greppable record debt; the children[] entry's additive `quota_signal` field (State file) carries the same observation for dispatched children in that field's own continue/percent format (its paragraph in the State file section), the decision_reason token remaining the authoritative record. The account governor's pressure class is an additional quota-signal source recorded through `pressure_class`: it never replaces the probe-derived slugs (the probe stays the per-window truth); its load shaping runs through the Account governor policy paragraph below, where the class `exhausted` parks both lanes regardless of slug.

Account governor policy (2026-09-28, account-quota-governor plan): the account-level governor owns one shared host state file (`~/.ai-playbook/runtime/quota-governor-state.json`, lock-protected atomic replace, schema version 1) that every repository's automations read and update, so the fleet cooperates on the account-wide window instead of racing it. The turn consults the class through the refresh report or `python3 scripts/quota_governor.py --consult` and obeys the returned per-lane `dispatch` verdicts; the policy table is owned by the script and never re-stated here, so skill and script cannot drift: `abundant` allows both lanes, `tightening` holds the execution lane above the reserve headroom floor, `constrained` defers execution and gates authoring behind its floor, `exhausted` defers both lanes with the reset time (displayed in the host's local zone) recorded in `decision_reason`, and `unknown` (unusable or stale-past-30-minutes state) keeps the existing defaults, fail-open. A deferred lane parks through the existing `pending_dispatch` path with the class and reset time in the record; the standing reserve protects interactive user work, which outranks all automation load by default.

Stop-before-exhaustion arm (the hard park arm; the operator's stop-while-remaining-drops-below-about-5-percent doctrine, 2026-10-12): at a primary-binding `used_percent` at or above 95 (the stop threshold; a secondary-binding reading stays report-only per the defer rule the overlay's Quota leg names), the boundary parks the remaining mandate instead of starting more work, with the timed resume at window start carried where the mandate owner arms or re-points a carrier at that window start (the re-arm, the successor dispatch, or the budget gates' own resume automation where the harness supports one), the resume carrier's window-start minute exempt from the distribution rule's spacing evaluation the way the operator-named minute is (window start is a wall-clock anchor, not a chosen minute; the runtime-fit and pricing fixing rules still apply); maintenance cadence without such a carrier resumes at the first boundary after the reset whose probe is fresh (the resume rule, not an unkept promise), and the reason token `stop-before-exhaustion` rides the park's existing surface, never a continuation. The primary-only scoping is a recorded limitation beside the arm's review clause (first false park, or one month of operation): a secondary-binding near-exhausted regime at the arm's boundaries starts work at the secondary window's risk, the operator stop doctrine of record being primary-scoped (2026-10-12), so the first secondary-window mid-run death is a recognized residual. A stop-threshold park never discharges in the same session; the first boundary after the reset whose probe is fresh discharges it. Routing by remainder kind: parkable kinds (execute, author, audit, retriage) park on the `pending_dispatch` path per its field paragraph in the State file section (the stop-threshold park write; no new writer class or field), the park write riding the successor duty's decision-first park-first shape and superseding any retained park record occupying the slot, the supersession recorded beside the `stop-before-exhaustion` token in the park's note (the displaced park's consult stays due and re-parks once the slot clears, its paired payload copy discharged in the superseding targeted edit, named by the note only when discharge is impossible, never orphaned), and the stop park is never skipped for an occupied slot (the emergency brake; the audit park's null-slot skip discipline is not the stop park's shape); EXEC-PROMPTS item transitions and ad-hoc boundaries record the hold under the Ad-hoc backlog arm's hold-with-recorded-reason vocabulary (the arm's own recorded form: blocked ad-hoc work holds with a recorded reason and never parks) with the reason carrying the `stop-before-exhaustion` token (so the enforcement park is distinguishable from a stranding on the route's own recorded-reason surface), naming the boundary's own budget_pause record beside it only where the boundary owns a Budget-gate sink (an execute-plan or authoring run does; a bare maintenance turn does not), never a state-file surface and never a `pending_dispatch` write. The park is deferral-class per guards.md's User-directed override rule: a user-directed override proceeds past it, and a recorded operator order (a clocked consult the operator named) proceeds at its requested minute (session interactivity is not required for the order's own dispatch), while every other unattended remainder parks; a probe that errors or reports unknown keeps the dead-probe posture below (downgraded precision, the boundary recorded unknown rather than skipped), so an unreadable probe never trips this arm.
- Runtime-fit rule: when minutes_remaining at the planned fire time on the primary window is less than the lane's expected runtime upper bound (execution 240 minutes; authoring 120 minutes), fire at reset_at_epoch instead, regardless of pricing preference, and record the comparison (expected versus remaining minutes) in the lane's decision_reason.
- When the probe output is not usable, apply the fallback pinned in `agents/skills/maintenance/zcode.md` ("Quota leg"). Dead probe output downgrades timing precision; it never blocks scheduling.
- When the final fire time lands inside the provider's published peak-pricing window, apply the overlay's usage-pricing rule: defer to the window's end so the child's run bills at off-peak rates, unless the starvation exception applies; before deferring for pricing, verify the deferred slot passes the runtime-fit rule, and when it does not, defer to reset_at_epoch instead. Starvation is named by observation: no child record with kind `execute` and `created_at` within the last 24 hours in the state file (fall back to the runtime listings when state writes have been failing), and the exception releases only the starved lane; starvation beats pricing, never the runtime-fit rule. An operator-named wall-clock time is exempt from this peak deferral: when the fire time is a recorded clocked operator order's requested minute (the operator set the time), the deferral does not apply and the order's fire stays at its requested minute (the survey's clocked-order consult arms it there). The pricing cache lives in the state file's `pricing_cache` field and wins when fresher than the overlay's tracked seed; the turn updates only that state cache (plus a memory note when the values changed) and never edits tracked skill files to re-pin pricing.
