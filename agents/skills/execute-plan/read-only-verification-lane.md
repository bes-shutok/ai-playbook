## Read-only verification lane

Use when the active plan matches the lane condition. The entry test is the plan-observable check, evaluated once at Phase 0 entry from the plan file: every task's `Files:` list declares none. The no-tracked-edit clause (no task edits a tracked path before the completion pass) is the invariant the stop rule enforces during the run, not a second entry test. A plan matching the condition runs this lane for the whole run; the full-flow contract stays byte-unchanged for every plan that does not match. A resumed run re-evaluates the same declarative condition and re-routes to the full flow when the condition no longer holds.

**Placement:** the lane defines its own placement rule through the router dispatch as a named exception to the Worktree-first standard's worktree default, so the run resolves to the primary checkout with no worktree, no execution claim, no transfer-in, and no closeout-baseline capture; for a lane-matching plan this classification supersedes conflicting duty text in the other execute-plan modules, including the vacated numbered hard gates and the standard's sanctioned in-checkout-arms enumeration, which the lane joins as a third sanctioned arm. Before any task work the run consults the live execution-claim surface and recorded witnesses and refuses to start while any of them occupies the primary checkout, reusing the standard's primary-placement serialization semantics while itself taking no claim, so the consult is one-directional: it honors live claims and recorded witnesses but leaves no claim-surface holder of its own. The run works on the primary checkout's current branch only after verifying it equals the base branch at run start, standing down with the standard's two-option remedy (check out the base branch or take the worktree lane) when it does not.

**Vacuous duties:** per-task implement workers, intermediate task reviews, per-task light-boundary commits, the Phase 3 review panel, the suite-policy resolution machinery, and the per-boundary continuity probe do not run under this lane; tasks run inline in the orchestrator with evidence recorded in the session manifest task rows. Any duty not listed as vacuous runs per its owning module unchanged.

**Retained duties:** the run keeps the session bootstrap and manifest duties including `runtime_state.json` and `pre_archive_receipt`; the plan readiness gate; the plans skill-gate marker before every plan-file edit; plan checkbox progress marking; the Phase 2 Validation Commands run recorded with fresh command identities and results; and the context budget checkpoint ladder at its safe boundaries. Each retained duty follows its owning module unchanged.

**Execution receipt:** at the Phase 3 exit position, the run writes the plans-egress pointer record into the resolved reviews home, named `<date>-plan-review-<plan-slug>-exec-r<N>.md`, carrying the SHA-256 of the final plan bytes the archive commit will carry for the archived path and the explicit statement that no code review panel ran because the plan's tasks edit no tracked file, and pointing at the Phase 2 validation evidence and the session manifest task rows instead of a code-review pair; the record is refreshed after any same-commit plan body edit per the archive module's plans-egress pointer record duty; this record is the lane's execution receipt.

**Archive and closeout:** the archive move keeps its document-registry row update and `doc_registry_validator.py validate`; the archive-egress check runs unchanged with this record satisfying its exec-review-record leg; and the Phase 5 closeout runs minus its worktree legs.

**Stop rule:** a task discovered editing a tracked file stops the run at that task boundary with a report naming the task and the edited path; resume follows the existing interruption rules.

**Disclosure duty:** the run report names the lane and lists the vacuous duties, so the reduced path is disclosed, never improvised silently.
